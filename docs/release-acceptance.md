## 故障及边界证据

- 余额仅够一单时 20 个竞争提交，只有一单成功；批次余额不足全单回滚；并发重复请求不重复预留或扣费。
- 一批一成功一失败时仅成功项消费；取消竞争、过期 Worker 回写、迟到产物隔离、无效图像及限流恢复均覆盖。
- 数据库已提交而 Redis 入队失败时 Outbox 保留；重建调度不重复业务副作用；浏览器夹具实际停止并重启 Worker，持久排队任务最终交付且仅消费一次。
- 25 条结果跨页选择后导出固定 2 条，验证 ZIP 包含两张 PNG；完整流程验证 CSV/JSON 清单与授权下载。
- 跨用户素材/任务/导出请求拒绝；BYOK 绑定错误供应商拒绝；封禁后已有浏览器会话失效且审计只写一次。
- 支付签名 fixture、事件重放/乱序、实际 invoice 周期、部分退款、消费权益审核、佣金负向调整、败诉争议结案与补偿幂等均覆盖。
- 订阅请求丢响应使用原幂等键恢复；超过 23 小时转人工核查，不自动发起可能重复的支付写操作。

## 运行记录与限制

自动化输出位于忽略目录 `test-results/` 和 `playwright-report/`；CI 会上传报告附件。GitHub Actions 已配置完整验收、恢复、容量和依赖扫描，远端实际执行结果以 GitHub 为准。

首次最终浏览器回归有三处断言失败，分别是主题错误地检查 class 而非 data-theme，以及失效会话预期 undefined 而实际协议为 null。修正测试后完整 22 项重跑通过。正常原生包安装最初因 Node 未使用系统代理而下载重置，按系统已有代理配置 Node 后重新 npm ci 成功；未忽略安装脚本、未降低 TLS 校验。

干净安装复核另发现测试开始前缺少 Prisma Client 生成步骤，已加入 `pretest:acceptance`，直接执行整体验收时自动生成 Client，避免依赖已有 node_modules 中的生成文件。

安装仍有上游旧工具包 deprecated 提示，不是 ESLint 或当前漏洞扫描结果；最终审计无活动例外。C2PA 默认关闭，安装器下载的上游测试证书不会被应用用于签名。

V1 使用 contain 补边交付，不提供交互裁切、局部重绘、团队空间及固定身份多角度套图。商家核心流程双语，既有部分管理页面保留中文。模型成本为适配器估算，QA 和像素规格不能代表服装保真、平台过审或商业使用权。

真实 AI、Stripe、OAuth/邮件投递、云存储、真实 C2PA 签名、部署监控/备份和素材授权均按约定延期，负责人职责、步骤及标准见 [延期验收清单](real-environment-acceptance.md)。当前结论是开发候选版本完成本地验收，不是已验证真实生产可用。
