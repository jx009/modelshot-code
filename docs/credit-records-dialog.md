# 积分充值与记录弹窗

## 用户入口

- 充值卡片金额在上、积分在下。支付方式、选中套餐、到账轮询保持原流程。
- 充值弹窗的「充值记录」切换到购买记录；记录弹窗的「充值积分」切换回充值。
- `RechargeProvider` 只维护一个当前弹窗状态，切换不叠窗，关闭回到原页面和原入口焦点。
- 头像菜单只保留购买积分、使用记录、购买记录等有效入口，删除使用指南和旧账户账单入口。
- `/[locale]/account` 不再包含旧 UI，仅跳转到首页并打开购买记录；`?tab=usage` 打开使用记录。关闭清除入口参数，刷新不会重新弹出。

## 记录数据

`GET /api/account?tab=orders|usage&page=1` 以当前登录用户身份查询；响应禁止缓存。

- 购买记录：时间、充值金额、到账积分、状态。只查询积分订单，不返回套餐内部 ID 或套餐快照。
- 到账积分来源于该订单实际 `purchase` 账本入账，减去对应 `payment_refund` 扣回；不使用现价套餐或可变配置推算。待支付、失败订单显示未到账占位符。
- 使用记录：依据关联 `TryOn.snapshot.tool` 显示具体工具；语言任务使用 `snapshot.purpose` 区分提示词优化、创作规划、电商套图规划、焦点识别。缺失任务信息时显示历史任务，不能猜工具。
- 原始 reason、任务 ID、提示词等内部字段不返回记录列表，说明列使用面向用户的事件说明。
- 在数据库分页之前过滤 `amount = 0`，不删除账本或影响审计。每页多取一条判断下一页，避免空页和漏项。
- 无数据库结构变更，不改变余额、扣费、退款或支付回调写入逻辑。

## 验证

- `tests/integration/account-records.test.mjs`：真实数据库的所有权、具体任务类型、分页、零流水过滤、到账与退款。
- `tests/ui/billing-records.spec.mjs`：桌面/手机布局、互斥弹窗、旧链接兼容、错误与登录状态、键盘关闭和焦点恢复。
- `tests/ui/recharge.spec.mjs`：原有支付状态刷新、币种、登录恢复等回归。
