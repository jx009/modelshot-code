# 页面与画布加载排查（2026-10-18）

## 点击后延迟跳转（2026-10-21）

- 原先主要在悬停、聚焦或触摸时才预取路由，快速点击仍可能等待路由请求；已有 `loading.js` 并不意味着未预取的路由能立刻切换。
- 点击后立即在本地切换到目标页标题和内容骨架，隐藏旧内容，不再用“旧页面上方加一个正在打开提示”替代页面切换。创作区和管理台内跳转保留外壳、更新导航选中项，跨外壳跳转使用根内容骨架；待 Next 提交路由再替换真实内容。浏览器地址及历史仍由 Next 管理，不提前伪造 URL。
- 内容边界位于全局导航状态之下，移动菜单关闭不再影响切换。旧内容隐藏期间保留挂载以免重启请求或重置草稿；等待超过 8 秒在目标骨架内提供重新打开入口，不自动刷新。导航栏可继续切换其他入口，旧跳转完成不能清除新跳转状态。
- 创作主导航、管理台的数据看板和用户管理入口在页面加载后错峰开启 `auto` 预取；动态路由按 Next 的 loading 边界预取，其他管理入口和内容卡片仍按用户意图预取。不在空闲预取阶段加载 Konva 画布模块，省流量、2G 或隐藏页面不执行空闲预热。
- 保留服务端鉴权及用户数据缓存限制。覆盖 `NavigationLink` 以及首页、案例配方、电商入口的程序化跳转；业务按钮跳转前必须完成的上传、建档等操作仍保留自身状态。预取不能消除香港回源 TLS 超时、服务端执行或浏览器主线程阻塞。
- 补充导航反馈生命周期及错峰预取回归用例；本机仅做改动文件的静态语法、导入路径和差异检查，不运行构建或测试，交互及真实耗时仍需上线验收。

## 任务与工具交互补充（2026-10-22）

- 保留画布局部订阅、组件缓存、工具拆包、完整路由预取和上传并发 2。新任务提交成功后显式更新订阅版本，唤醒已停止的 SSE/轮询；旧请求和旧连接通过 abort 隔离，任务完成后仍停止空闲轮询。
- 普通云端保存允许本地草稿写入失败后继续，同时保留本地保存失败提示。生成任务提交前的显式 `flushLocal()` 仍会传播错误，不绕过提交幂等记录的持久化要求。
- 首页和画布选择/粘贴图片后立即展示独立的本地缩略图队列，标明等待、上传并登记、失败状态。每张完成后立即加入参考图或画布，不等待整批最慢的图片；临时 Blob URL 不写入项目，完成、移除或离开组件后释放。当前是阶段反馈，不是字节上传百分比。画布按完成顺序添加图层，每张沿用现有撤销记录；只在首张成功时自动适应视图，避免后续上传打断用户平移。
- 导出和图片预览仍按需加载，下载模块期间先显示可关闭的窗口，失败时给出明确提示；其他异步工具补充加载文案。关闭等待窗口后，模块加载完成不会自行重新打开。
- 补充空闲项目再次提交、旧快照隔离、断线轮询、保存降级、预览资源释放、逐张上传及工具加载用例。只做限定文件的静态校验，本机不运行测试或构建；真实网络下的交互表现交由 CI/上线验收。

## 项目列表和切换补充（2026-10-22）

- 画布项目管理窗口先打开，再加载列表；加载中可关闭，读取失败可在窗口内重试。列表改用分页元数据接口，首批 24 条，其余通过“查看全部项目”进入项目库。最近项目选择后立即收起列表。
- 项目库、最近项目和画布项目管理共享按用户、筛选条件、游标隔离的 30 秒内存缓存及在途读取。新鲜数据不重复请求；单个消费者退出不会取消其他消费者的请求，最后一个退出才中止读取。画布保存和项目库改名、删除、恢复使相关缓存失效；失效前的响应不能重新填充缓存。缓存只在当前浏览器运行时生效，不把私有接口变为公共缓存。
- 项目库改名、确认删除、恢复先更新界面，再同步服务器；失败回滚并提示，结束后重新读取当前筛选的第一页校准版本和游标。保留删除确认、服务端权限与版本校验，同一组件内串行修改，过期列表读取不能覆盖乐观结果。
- 画布切换立即进入明确的等待状态，禁止重复切换和继续编辑正在离开的快照。仍先确认旧项目保存，再读取目标项目；保存失败保留旧项目和修改。这不是“脏项目也能后台保存并瞬间切换”，没有为了表面流畅绕过保存幂等及冲突保护。
- 大画布附加图层页从无上限并发改为并发 2，保持顺序及版本校验，失败中止剩余请求，继续沿用打开请求的 15 秒总期限。这限制瞬时服务器压力，不保证大画布总加载耗时更短。
- 本轮未实现对象级增量保存、COS multipart 或服务端任务发布订阅；这些涉及协议、校验和恢复路径，不能直接照搬公开前端调查。没有数据库结构变更。新增用例覆盖请求合并/取消/失效/用户隔离、即时窗口、乐观失败回滚、切换保存保护和图层分页顺序；仅静态校验，不在小服务器运行构建或测试套件。

## 慢请求排查后的定向修复（2026-10-22）

- 生产采样显示：源站本机 HTTPS 接口约 16ms；香港直接连接同一源站的请求既有约 0.88s 成功，也有正文未接收完整的 15s 超时。浏览器请求列表还出现模型配置读取约 1 分钟、图标约 18s、案例图优化约 26s。不能将这些耗时都当作数据库计算时间，也不能据此断定所有问题都属于线路。
- 模型配置页原先直接 `fetch`，没有读取期限或离页取消。改用带 15s 期限的读取，期限覆盖响应正文解析；离页/新读取取消旧请求，失败展示可重试状态，格式异常不显示为空模型列表。配置写入和付费连接测试协议不变，不自动重试这些操作。超时控制减少无反馈等待，不代表网络或后端已经加速。
- 关闭 NextAuth 每次页面重新可见就触发的会话刷新，保留 60s 周期刷新、登录退出及跨标签同步、服务端权限校验和现有异常会话恢复。网络恢复触发的显式刷新增加在途保护和 30s 间隔。请求列表缺少时间轴和触发事件，尚不能确认所有重复 session 均源于可见性切换，也不声称已合并 NextAuth 内部的全部读取。
- 八张固定电商案例 WebP 改为构建期静态导入并直接交付，不再走 `/_next/image` 实时优化。它们随 `.next/static` 进入现有香港发布流程；不依赖额外 public 图片 Nginx 规则。代价是直接传输已有 WebP 原文件（约 22–274KB），不再按视口生成更小尺寸。此改动不适用于用户私有素材，也不解决 `/icon.svg` 的回源问题。实际静态命中仍需发布后验证。
- 不仅凭不同 `_rsc` 参数判断为重复请求，不盲目关闭全部预取。RSC 仍可能受回源故障影响，后续需要带 Timing/请求头的浏览器记录与 Nginx 日志关联。当前修复不是“全部卡顿已解决”的承诺。

## 最近两次发布的回归审查与结构性修复（2026-10-22）

- 对照 `33eb9f5 → cb9143d → 5592b1c`，确认 `cb9143d` 将 idle 预取从 `auto` 页面壳升级为完整动态页面，并将创作导航预取时间改为 `500 + index * 250ms`；前一版本为 `1500 + index * 1000ms`。这让未点击模块也请求完整 RSC，扩大了首屏后的后台回源工作量。它是确认的请求放大回归，但现有样本不足以把所有分钟级请求都归因于它。
- 创作导航和管理导航取消自动批量预取。通用链接只在真实鼠标停留/键盘焦点/持续触摸 150ms 后预取；快速掠过、立即点击、触摸结束、离页和不可见元素不启动延迟预取。失去悬停/焦点后不再保持完整预取开关。旧 `idle` 模式兼容为意图触发，不再自动发请求。点击反馈仍即时，不延迟点击本身。
- 管理台新增客户端模块选择层，覆盖数据看板、用户、运行与账务、模型、分辨率积分、云存储、工具配置七个模块。导航直接更新本地 URL/模块，再由模块读取 API，取消这些导航上的 Next RSC 预取和页面导航请求；只懒加载当前模块 JS，不同时下载七个模块。离开模块会卸载其组件，已有支持取消的读取随之终止。浏览器后退/前进与 locale 保留；其他管理页及跨区导航继续走原有 Next 路由。
- 使用本版本 Next 文档支持的原生 History API 集成，不改 React/Next 技术栈。首次加载、刷新、直接访问仍执行原有 AdminLayout 服务端鉴权；管理 API 的实时权限/封禁校验不变，没有把用户数据放进公共缓存。客户端模块层只选择界面，不能授予访问权限。
- 模型配置 GET 响应添加 `Server-Timing: auth/query/serialize/total`，总执行超过 1s 才记录不含凭据的阶段耗时。该计时截至响应构造，不包含代理排队或正文网络传输；它用于证实一分钟耗时发生在哪段，不把超时设置当作加速。响应始终 `private, no-store`，读接口不调用模型。
- 已补模块本地导航/离页取消/历史/普通链接兼容、无背景预取/意图取消、接口计时与权限回归用例。仍只运行改动文件的语法、导入及基础规则静态校验；未运行构建或测试套件。上线需确认七个模块切换不再发 `_rsc`，数据请求开始时间不再串行等待页面响应；不能在无实测的情况下保证所有 API 秒回。

## 线上观测

以 `www.letaidraw.com` 的公开页面和未登录画布做读取测试，没有使用用户账号或生成图片。

- 静态资源返回 `X-HK-Static: local`，证实 Action 上传与香港本地读取生效。
- 一轮浏览器采样中，香港本地的约 9 KB JS 与约 1.6 KB CSS 均出现约 10 秒请求耗时，页面请求也出现约 10.7 秒；这些请求最终返回 200。
- 使用禁用系统代理的浏览器另测，访客画布首次可见约 1.7–3.7 秒，首页切回画布约 1.4–2.9 秒。此轮最终使用 HTTP/2，没有复现永久黑屏。不同时间、连接、代理环境不能直接作性能提升前后对比，也不能据此断定 HTTP/3 是原因。
- 截图展示的是 Fetch/XHR，无法从中判断具体私有图片的大小、传输与解码时间。私有画布图片不能在未登录测试中访问。

## 已发现并修复的代码问题

1. 全站每次路径改变调用 NextAuth `update()`，引入 CSRF 和 session 请求，并短暂把状态切为 loading。去除该刷新，保留定时、焦点、网络恢复和显式账户操作刷新；丢失登录态后的服务器验证恢复仍保留。
2. `useStudioProject` 依赖原始 sessionLoading，已知用户后台刷新时也会重新读取并重置画布。现在仅首次尚无用户身份时等待登录，工具能力与任务订阅同样不因 loading 波动重启。
3. 重开已有画布时，云端请求结束之前不显示本机副本。现在先绘制当前用户的本机草稿，版本核对完成前禁用编辑提交，保留原有未确认保存与版本冲突处理。
4. 云端读取缺少期限与明确的失败重试。现在单次打开最多等待 15 秒，退出/切换取消旧请求；没有可用副本时显示“重试打开”，不持续显示正在打开。
5. 图片只因占屏较大就自动下载原始文件，放大了跨洋流量。常规浏览使用 320/640/1280 WebP；只有选中图片、显示像素超过 1280 且稳定放大 700ms 才加载原图。原图下载、工具输入和导出不变。
6. 公告不再每次切页重新请求，仍定时刷新并响应焦点和管理更新事件。
7. 浏览器内动态页面片段缓存 30 秒，减少短时间返回已打开页面的 RSC 往返。这不是共享 HTTP 缓存，私有 API 仍正常鉴权。

## 验证与后续边界

回归覆盖后台 session 刷新时文档不重读、本地副本先显示且等待版本校验、加载超时/取消/重试、原图按需加载，以及登录态恢复。

这些代码修改不改变香港与美国的带宽、丢包或服务器负载，也不会把私有图片变成香港公开静态文件。私有图片继续通过美国鉴权接口。不能把所有 `/api/assets/*` 改成匿名共享缓存来追求速度。

上线后先看 Img 请求的耗时、大小、`Server-Timing`（authorize/preview）与浏览器 Timing 中的等待/下载时间，再决定是预览持久化、带鉴权的香港图片缓存，还是更换线路。若香港本地极小资源依旧数秒，应分别从香港本机和国内网络测同一静态 URL，区分源站计算与入口线路。
