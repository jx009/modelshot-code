# 椒图整站对标与电商 Agent 重设计

更新：2026-09-26。本方案替代上一版画布为主的范围定义。

## 对标依据
已实际检查椒图首页、电商输入和灵感发现，以及用户的豆袋沙发详情页截图。首页提供对话 / 快速 / 电商套图切换，产品图 / 参考图、品牌、平台、国家、语言和详细商品描述。案例瀑布流以视觉内容为主体，点击案例回填创作要求。截图包含主视觉、生活场景、工艺特写、多场景网格与参考对照。登录后付费生成未实测，不能宣称效果对等。

## 实施顺序与验收
1. 整站入口：`/[locale]` 不再跳转旧 studio；深色侧栏、艺术化创作区、模式切换、作品瀑布流、分类搜索。摄影素材明确标注参考用途并记录来源。
2. 灵感与案例：`/explore` 分类和搜索；`/explore/[slug]` 完整案例、版式说明、提示词、使用版式。参数进入新 Agent / 画布。
3. 独立电商 Agent：`/commerce` 产品与风格参考上传，品牌、平台、地区、语言、商品事实、规格、受众。生成六屏可编辑分镜（主视觉 / 卖点 / 特写 / 场景 / 规格 / 收尾），可修改标题、正文、提示词、顺序、版式。未连接模型时标明模板分镜。
4. 任务：每屏始终引用原始商品图，独立传递风格参考图；保留现有鉴权、私有存储、积分、幂等、Outbox 和队列。独立任务提交后关页不丢失；失败屏可单独重试。
5. 交付：准确文字由代码排版；实时预览、模块图、长图和 JSON 清单 ZIP；原图排版与真实 AI 结果区分；可带图像和可编辑文字进入画布。
6. 验收：案例回填、双图引用、项目持久化、重复提交与失败恢复、原图导出、真实素材预览、桌面手机、构建和相关回归。模型未配置时不能以测试色块冒充效果验收。

| 摄影视觉风格 | buluslan/gpt-image2-ecommerce，MIT | 复用摄影/杂志/生活方式 JSON 模板字段，不运行其 CLI |
| 生产服务 | modelshot-code | 复用鉴权、账本、存储、队列；重新做电商界面及计划，不调用旧正则 Agent |

不添加为调度而调度的重型 Agent 框架；已有队列承担执行可靠性。开源 Skill 不等于可嵌入网站的完整生产服务。

## 交付边界
本轮必须提供首页、灵感、案例详情、新电商工作台、分镜编辑、原图排版导出、真实图像任务协议和画布衔接。付费模型效果需配置后对商品一致性、文字、复杂细节、时延、成本与失败率进行单独验收。会员支付与账户继续使用现有实现；不宣称椒图全部登录后页面已像素级一致。

## 后续差距的具体实施顺序（尚未交付）

### A. 工艺与场景四格

1. 在 commerce schema 中加入带稳定 ID 的 module/slot 层级，详情和场景模块各支持 4 个独立 slot；保留旧六屏数据的迁移读取。
2. 策划器分别输出“可见工艺特写”和“不同场景”方向；缺少背面/内部素材时不编造结构，应提示补图。
3. 在任务快照、幂等键、结果 manifest 中增加 slot ID。所有 slot 使用原始商品身份，独立生成、计价、重试。
4. 编排器按模块渲染四格；每格可换图、调整焦点和文字。预览、长图、逐模块下载、画布采用相同几何布局。
5. 用商品一致性、槽位错配、失败恢复和整页尺寸测试验收，不用同一张图重复裁剪冒充四次场景生成。

### B. 从工作流到可验收 Agent

1. 连接真实图像与视觉供应商后，选择家居、护肤、数码各一件授权商品；每件至少提供正面、细节和使用场景参考。
2. 让视觉模型提取可见商品特征，生成风格说明和模块计划，用户可核对事实。
3. 对每格输出检查结构/颜色/标识是否保持、参考产品是否串入、文案有无虚构。先记录问题，再加入有成本上限的重试/候选选择，不设无限循环。
4. 每套记录生成耗时、调用次数、费用、失败率、人工修改次数；将经过人工审核的真实结果补入案例库。
5. 质量验收通过后再开放模型默认项与正式价格。协议测试通过不等于效果通过。

### C. 剩余整站对标

补齐账户、会员、完整素材管理的视觉统一；逐项实测椒图已授权访问的登录后交互，记录截图对照与功能差异。未知功能不得推断为已复刻。保留当前品牌与素材来源，页面调性和交互布局对标原站。
