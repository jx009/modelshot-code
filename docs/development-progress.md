## 关键业务保证

每个生成输出关联独立预留及原始消费流水。提交 N 张时全部预留原子完成；成功私有保存原图才结算，没有可交付产物时释放。QA 和交付衍生步骤失败不再次生成或收费。BYOK 不消耗平台生成积分，也不会跨供应商或回退平台付费密钥。

PostgreSQL 为任务及资金事实来源。Outbox 至少一次投递，Worker 用数据库唯一键、状态条件及递增 fence 拒绝重复或过期回写。请求未知进入对账，15 分钟期限后关闭交付并释放，迟到产物隔离。外部生成不宣称天然恰好一次。

支付按 eventId 和业务对象双重幂等；额度使用实际 invoice 周期。金额为 USD cents，积分单独计量。退款回收对应购买批次，已消耗或预留进入人工审核；争议败诉可按核查记录结案并冲回佣金。超过外部幂等期限的写操作转 review，ROOT 提供平台核查引用和原因后处理，成功退款仍由 webhook 确认。

所有用户素材经解码校验、重编码后进入私有存储；旧公开 uploads 路径返回 404。引用存在时不能删除，删除保留 7 天，导出保留 24 小时。账务和审计不随归档删除。

## 验证入口

`npm run test:acceptance` 包含全量 lint、设计/双语扫描、单元、真实本地服务集成、生产构建及桌面/移动浏览器流程。`test:recovery` 演练 pg_dump/pg_restore；`test:capacity` 验证 20 并发幂等/不同提交及账本守恒；`check:dependencies` 扫描锁定依赖。

静态检查、52 项单元测试、42 项集成测试、22 项浏览器测试和生产构建已通过。干净安装及最终复核记录见 `release-acceptance.md`。C2PA 原生模块已成功安装和加载，但不启用测试证书，不把模块加载当作真实签名验收。

## V1 明确边界

- 交付采用精确尺寸的白底 contain 补边，保留整件服装；不提供交互裁切、局部重绘、多角度身份一致性或团队协作。
- 支持供应商能力以版本化表为准。提示词控制不代表真实模型效果已验收，配置复用不代表像素级复现。
- 供应商成本为适配器估算，真实成本、吞吐量和质量需真实样本/账单核验。
- 自动 QA 默认为关闭，可显示 skipped/error；不伪造通过分数，不保证电商审核或商业权利。
- 商家主要工作流双语，既有运营管理页面保留中文；新增异常处理页面双语。
- V1 不执行历史数据回填或正式环境切换；当前 12 个迁移用于新库安装与后续版本追踪。
