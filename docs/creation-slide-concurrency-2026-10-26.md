# PPT 并发与失败恢复（2026-10-26）

## 已确认的代码问题

- 大纲确认后，页面依次依赖上一页；用户语言任务准入只允许一个活动任务；调度器只查看第一条未完成任务。这三层共同造成串行。
- HTML 校验异常和供应商连接异常曾被合并为 `LANGUAGE_RESULT_UNAVAILABLE`；格式错误缺少定位信息。截图的旧错误码不能证明具体是哪条校验失败或上游网络故障。

## 本次行为

- 每个用户最多两个活动 PPT 页面语言任务，在用户行锁内检查准入。单个 worker 默认并发为 2，仍尊重已有 `CREATION_LANGUAGE_CONCURRENCY`（1–4）配置；全局队列上限不变。并发 2 是上限，不保证整体耗时恰好减半。
- 每页只依赖已确认的大纲和该页引用的配图。最多两张共享配图分别依赖大纲，通过已有图片队列执行；不再相互等待。不依赖配图的页面可以先生成。
- 提交一页后立即唤醒调度器填充空闲槽位。任意一页先完成就先保存，在作品中按已确认大纲排序，并保留已完成页上的用户修改。
- 某页模型失败或结果保存失败时继续其他独立页，全部活动任务处理完再将任务标记为失败。模型失败的预算释放只处理一次；已成功模型调用的结果保存失败保留付费结果，显式恢复时不重新调用模型。
- 取消向所有活动任务发出请求，逐个结算后结束；汇总只在所有依赖成功后运行。
- 原有串行任务在用户明确恢复时更新未完成页和配图的依赖；已完成的步骤保留。运行中的旧计划不会直接改写。

## 格式和诊断

- 对新生成的 HTML 移除 CSS 注释并修复重复/非法节点标识，然后执行原有严格校验；编辑已有页面时不做这种规范化。脚本、事件属性、外部资源、非本人素材等继续拒绝。
- 接受单个完整 Markdown JSON 代码围栏；不猜补截断 JSON，不接受解释性前后文。
- 记录 `CREATION_LANGUAGE_FAILED`，含 jobId、purpose、错误码、HTTP 状态和最多五条校验路径；不记录提示词、正文、HTML、密钥或请求头。区分超时、限流、认证失败、连接失败、服务端错误及页面校验错误。
- SDK 与执行器的模型请求超时均为 180 秒。不通过自动重发已提交的模型请求解决错误，避免重复计费。已提交但无结果检查点的恢复仍返回 `LANGUAGE_RESULT_UNAVAILABLE`。
