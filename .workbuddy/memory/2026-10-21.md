## 首页布局定位结论

- `.cr-home-composer`（输入卡片）是普通文档流元素，无 position，不 sticky / 不 fixed；滚动时随 hero 一起移出视口
- 宽度：discover.css 原规则 `max-width:730px;margin:31px auto 0`，被 parity.css 的 `.cr-creation-hero .cr-home-composer{max-width:none}` 覆盖，实际受 `.cr-hero-content{max-width:840px}` 约束并居中
- 卡片高度靠 textarea 固定高度（parity 下 min-height:110px）撑住，输入内容变化不跳动
- 唯一一次性动画：`animation: scale-in 450ms ... both`，播完停在终态
- 页面里真正 sticky 的只有顶栏（滚动 48px 变胶囊）、移动端侧边栏导航条、案例详情 `.cr-detail-info`、电商页 `.cm-direction-board`；大图预览 `.ig-full-image` 是 fixed 覆盖层

## 公告条与首页 stacking

- `.site-announcement` 是 `position:fixed; inset:0 0 auto; z-index:60`，高度 min-height 48px（padding 9px 52px），用 `.announcement-spacer` + `--site-announcement-height` 在流里占位
- 首页 `/` 的 Navbar 返回 null（Navbar.js 里路径白名单），所以首页栈序：公告(fixed 48) → cr-topbar(sticky 64, top=公告高) → hero(padding-top 56, atelier 覆盖 parity 的 64) → 品牌 logo 行(76, margin-bottom 22) → 副标题 → composer(margin-top 28)
- 公告底边到 composer 顶边约 310px，视觉上不挨着；因公告 fixed，滚动时 composer 会从公告下方穿过并被它遮住
