# 椒图与来塔的加载路径对照

## 证据与范围

2026-10-19 核对 10 月 17 日保存的椒图公开构建，并用同一台机器、同一 Chromium、禁用系统代理、各自全新浏览器上下文读取两个公开首页。没有登录私有画布、没有提交生成任务。以下单次采样不是 P95，也不能推出所有用户的性能差值。

| 本轮观测 | 椒图 `www.jiaotuai.cn` | 来塔 `www.letaidraw.com/zh` |
| --- | --- | --- |
| 首页首字节（从导航开始） | 358ms | 5324ms |
| DOMContentLoaded | 413ms | 11886ms |
| 图片路径 | `cdn.jiaotuai.cn`，可见 `imageMogr2/format/webp/interlace/1/thumbnail/640x/quality/75` | 公开案例经 `/_next/image` |
| 抽样图片缓存 | `max-age=31536000`、`Age: 856101`、`Server: tencent-cos` | `public, max-age=14400, must-revalidate` |
| 静态 JS | 抽样 `public, max-age=2592000`，有 Age | `X-HK-Static: local`；仍有约 743–4111 字节响应等待约 7.6s |

DOMContentLoaded 不代表全部界面与图片可用。图片缓存样本来自公开资源，不代表所有私有图的权限与缓存策略。资源大小使用浏览器 transferSize，含响应头。本轮没有通过私有账号验证黑屏，也没有访问两站运维后台。

可重复采集脚本与原始摘要暂存在本机 `tmp/compare-public-loading.mjs`、`tmp/public-loading-comparison.json`，不提交生成素材或账号信息。

## 1. 页面切换：不要让页面外壳反复等待跨洋响应

椒图公开构建是 Vue/Vite + Fabric，不是 Next.js。`C:/jxProject/jiaotu-research/2026-10-17/formatted/app-BA9moHhR.js` 的路由表使用客户端动态导入。代码和模块加载完成后的路由切换不需要 Next RSC 响应；业务数据仍需要 API。存在 KeepAlive 通用代码，但路由表未证实画布开启 keepAlive，不能据此宣称画布一直驻留。

来塔 `src/app/[locale]/studio-v2/page.js` 在服务器读取 searchParams 后传给工作台，路由冷缓存/失效时仍需页面数据往返。香港当前本地化的是 `/_next/static/`，不是所有页面、API、优化图片。

“正在打开”有两层：`NavigationLink`/路由 loading 可能发生在工作台挂载之前；`useStudioProject` 的 loading 则发生在工作台内。上一提交的 15 秒限制仅约束云文档读取，不约束前一层。30 秒客户端路由缓存能减少热切换等待，不能覆盖所有冷打开。

后续应把画布不含私有数据的外壳与 URL 参数读取拆开，验证静态/预加载路径，减少外壳依赖动态页面响应。保留 Next.js 即可，不需要为此迁移 Vue。不能把含登录数据的页面整体放入匿名共享缓存。

## 2. 图片传输与缩图：当前还没有完成资源分发对标

椒图 `request-CIU59nn2.js:546` 可见图片处理 URL 组装；本轮在线图片确实来自独立 CDN 域名并带 640 宽、WebP、quality/75 参数。COS/图片处理与缓存响应是可确认事实，不能据此确定后端服务器位于美国或香港，也不能确认每种私有图都是匿名公开的。

来塔私有图链路由代码可确认：浏览器 → 香港 → 美国 `/api/assets/[id]` → 登录与归属检查 → 对象存储。预览未命中时，`src/lib/domain/assets/preview.js` 读取原图，用 Sharp 生成 WebP；现有缓存是进程内 32MB，进程重启/淘汰会再次生成。浏览器本身已有 private 长缓存，不是每次查看必然重新下载。

应优先持久化按 checksum/尺寸/格式版本区分的预览，热门预览在入库后异步准备；再对公开案例接入香港静态分发，对私有图采用短期签名 URL 或每次边缘鉴权后再读缓存。不能直接给 `/api/assets/*` 开匿名公共缓存。此轮没有修改图片存储部署或伪称已接入 CDN。

## 3. 图片并发与取消：已复现并修复的代码缺陷

椒图 `ChatEditor-D1DiWSrs.js:2644–2804` 在 fetch 时传入 AbortSignal，再将 Blob 送入四并发解码/处理队列；取消同样传入队列。这个“四并发”不等于四个网络请求。

来塔此前把整个 Image 下载与解码一起放入四并发队列。组件取消只拒绝自身等待，底层 Image 没有停止，排队任务也没有移除。一个任务有两次、每次 25 秒的尝试，四张慢图可以长时间占住全部名额，影响重新打开或切换项目。

本机受控复现：四个旧图片任务阻塞 → 全部调用者取消 → 请求四张新图片。修改前新任务启动 **0/4**；修改后 **4/4**，旧 Image 清空 src、定时器移除，未启动的任务从队列删除。

修复使用共享任务的消费者计数：仅最后一个消费者退出才取消底层任务，避免画布退出误伤仍在使用同一张图片的导出或其他组件；完成的解码仍复用。当前保留四并发下载/解码总限额，没有未经验证照搬参考站的下载并发。

## 4. 恢复和绘制：几何先到，图片逐张补齐

椒图 `Main-D9d0GUUp.js:24914–25117` 反序列化布局、替换资源 URL、加入占位并聚焦，再异步恢复实际图片。单张图失败不应阻塞整张画布。大图显示降采样、原图按视口恢复、异步解码及 RAF 合帧，主要改善绘制和内存；不等于缩短模型生成时间。

来塔已有视口加载、分辨率预览、解码复用，上一提交补了本机草稿先显示和选中放大后才读取原图。本轮继续修复加载取消。仍应分别测量路由可见、项目几何可见、首张图片可见、所有可见图完成，不能用一个“加载完成”掩盖不同等待。

## 实施优先级

1. 本轮交付：修复取消不释放下载名额；回归同 URL 重开、共享调用、排队取消、超时重试与解码复用。
2. 页面外壳：减少冷切换的 RSC 依赖，预加载画布代码，给路由级失败提供明确恢复；独立验收。
3. 持久化预览：减少首次读取时的原图下载和临时缩图；公开图片与私有图片采用各自的分发权限。
4. 入口实测：同一小文件分别从香港本机与国内网络读取，对照响应等待、下载、重传和服务器指标。当前香港本地 1KB 资源也需数秒，不能把所有延迟归到美国缩图；不能仅凭这次测试断言某个协议或供应商有问题。

代码修复、资源分发和入口网络要分别验收。上一轮消除了重复加载，但尚不能宣称整体体验已与椒图对等。
