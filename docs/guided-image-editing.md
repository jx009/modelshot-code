# 扩图、局部修改与中文反推提示词

## 2026-10-19 修正

此前工具同时发送原图、第二张绿色指示图和 alpha mask，还要求模型保留人工灰框，再裁框还原尺寸，比例偏差超过 2.5% 就丢弃结果。这个输入协议不是椒图已公开的前端协议，也不能假定每个兼容网关都支持。旧流程本身已经只有一次生图调用；这次简化的是输入协议和交付流程。

### 扩图

按椒图公开前端构造输入：目标画布填充纯绿色 #00ff00，原图按用户指定位置绘入。最长边限制 3072 像素，导出 JPEG（quality 99）；只发送这一张合成主图、目标比例/清晰度和要求，不追加原图副本或独立 alpha mask。网关实际 MIME 和文件扩展名匹配 JPEG。

sizeSource 显式携带目标画布尺寸；auto@1K/2K/4K 按目标计算，不能再按原图计算。OpenAI 兼容、方舟、DashScope 共用此约定。对话输入框的比例不覆盖扩图选区，仅取其分辨率档位；保留旧模型已知尺寸约束。

### 局部修改

按椒图公开前端构造输入：白底原图叠加纯绿色选区笔迹，最长边限制 3072 像素，导出 JPEG（quality 99），加用户主动提供的参考图。不再自动添加第二张指示图，也不发送独立 alpha mask。指令明确绿色是修改范围而非成品颜色，删除任务必须自然重建背景。不调用语言模型，不增加付费请求或自动重试。

### 结果与审计

- 交付模型返回的完整有效图片，不按假设的灰框裁剪、不拉伸、不把原图中心贴回、不因比例舍入或不同尺寸直接丢弃结果。资产服务仍校验格式、文件大小和像素上限。
- 返回比例明显不同会记录 PROVIDER_ASPECT_RATIO_DIFFERENT 元数据，同时保留实际宽高和请求宽高。这不代表保证所有模型都能按目标比例或保留全部主体细节。
- 提交之前写入 studio-image-request 处理步骤，记录实际指令、目标尺寸、输入模式、图片数量和是否发送 mask，不保存凭据或图片 base64。
- 兼容网关响应记录 HTTP 状态、图片结果类型和上游请求 ID；HTTP 400 不会被伪装成成功。
- 后台审计区分本站请求 ID 与上游请求 ID，并直接显示实际执行提示词。响应审计写入故障不会阻止有效结果交付。旧任务中已丢失的响应无法由升级补回。

### 中文反推

反推提示词明确要求简体中文正文，包括主体、动作、构图、场景、光线、色彩、材质、镜头与艺术风格。系统指令和最终图片消息均使用中文约束；英文关注点不会更改输出语言。品牌、人名和型号允许保留原文。仍只调用一次视觉语言模型。
