# 椒图整站对齐：交互调研与开发方案

日期：2026-09-29。状态：**已按本方案进入开发；项目、任务、素材、裁剪/导出与部分全站交互已实现，待部署与真实模型验收。并非整站 1:1 验收完成。**

实施与验证记录见 [本轮交付记录](jiaotu-parity-implementation-2026-09-29.md)。原方案的剩余范围继续保留。

本方案以本次登录后的参考站实测、用户截图和当前仓库代码为依据，更新 `jiaotu-development-plan.md` 中有关项目历史、素材管理、画布及整站对齐的范围。旧文档中未完成的内容不能视作已交付，旧工具供应商描述也不能覆盖当前后台路由配置。

## 1. 首先要改变什么

把产品组织成“一个项目承载一次完整创作”：第一段提示词成为默认项目名称，聊天、上传原图、每次生成与修改结果、画布布局和任务记录都属于这个项目。用户回到项目时继续上次工作，而不是面对若干张无上下文的图片。

参考站实际有两个独立概念：**项目库**保存创作会话，**素材库**保存可跨项目复用的素材。我们的界面也应明确分开。用户指出的历史记录问题成立；仓库虽然已有 `StudioDocument`，但命名、自动保存、URL、入口和列表呈现没有连成完整体验。

对齐范围包括页面布局、导航、功能入口、操作顺序、状态反馈、动效及真实输出。保留 ModelShot 名称、自有内容和后台能力配置，不用参考站商标、插画或案例素材冒充自己的内容。视觉与交互对齐不等于能从网页确认其私有模型、提示词或服务端架构。

### 必须维持的产品规则

- 原图与每次结果并列保留；物体移动得到完整场景，不能只交付抠出的前景。
- 框选、移动预览和局部修改中的临时平移，不退出工具、不清空选区。
- 用户选择生图模型；辅助语言模型由管理员配置，提示词优化等场景自动调用。
- 每个工具可配置专用供应商/模型，或继承用户选择的生图模型。分割、图层拆分等按能力校验；不能让一个不支持该功能的模型因名称相似就出现在选项里。
- 普通 CPU 服务器继续负责应用、队列和确定性图像处理；云模型通过 API 调用。此轮对齐不重新引入本地大型分割模型预热依赖。
- 一次明确的直接生成/工具提交只提交一次，不追加第二次“确认执行”。多步骤且费用发生变化的计划另有清晰交互。

### 动效实测样本

以下来自可见元素的计算样式，不是对整个网站的统一时长推断：

| 对象 | 观察到的数值/行为 | 对齐方式 |
|---|---|---|
| 按钮按压 | `scale(0.97)`，75ms | 按下即反馈，点击区域不随视觉缩放失效 |
| 导航与搜索 | 普通过渡约 150ms；搜索宽度约 36→214px，ease-out | 展开不遮住关键动作；键盘聚焦同样可用 |
| 次级显隐 | 关闭按钮透明度约 200ms | 不用 display 突切造成跳动 |
| 导航图标内部 | 个别图形约 420ms，首页门形约 500ms；文件夹微位移/缩放，素材图标局部旋转 | 图标内部细节动，保持导航容器稳定 |
| 图片加载 | 透明度过渡约 700ms | 解码完成淡入；这不是强制等待 700ms 才显示 |
| 工具面板 | 扩图面板 `emerge`，计算时长 300ms、ease | 进入/退出一致，模型请求不阻塞面板打开 |
| 其他入场 | 可见聊天内容 `enter-move` 约 1s；另有 `emerge` 1s 的容器 | 按场景测量，不给每个弹层强加 1s |
| 项目标题 | 样本“生成一只猫”的打字动画 200ms、steps(5)，带 reduced-motion 分支 | 仅名称首次出现使用；每次保存不重播 |

尚未建立完整逐帧录像、所有 easing/keyframes 或移动端动效基准。开发时将这些补为验收素材，不能宣称已完成全站像素与动效一致。

| 代码位置 | 已有能力 | 目前的问题 |
|---|---|---|
| `prisma/schema.prisma` 的 `StudioDocument` | 项目 ID、归属用户、名称、版本、JSON 内容、时间 | 缺少轻量列表元数据、命名来源、独立历史分页和视图恢复 |

| `src/app/api/studio/documents/[id]/route.js` | 项目读取/删除 | 当前 DELETE 真正删除文档并移除 studio 引用；若增加恢复，必须改数据语义而非只加回收站 UI |

| `src/lib/studio/tools.js` | 工具注册、参数校验与路由能力 | 图层最多 150、消息/任务/已应用列表最多 100；不能继续靠截断数组声称保存全部历史 |

**结论：沿用并完善 StudioDocument，不新增第二套“Project”表来承载同一会话。** 将用户可见名称统一为“项目”，旧业务记录以明确的兼容入口访问。

## 4. 项目历史与素材库的目标结构

```text
我的项目
└─ 生成一只猫（稳定 project/document ID）
   ├─ 首次提示词与后续聊天
   ├─ 上传原图、引用素材
   ├─ 生图结果 → 移动结果 → 局部修改结果（均保留来源）
   ├─ 画布位置、尺寸、旋转、可见性、分组
   ├─ 任务状态、输出、失败/重试记录
   └─ 最近视图与封面

素材库
├─ 全部素材 / 未分类 / 我的分类
├─ 上传素材与用户明确收藏的生成结果
└─ 回收站（素材条目，与项目删除分开）
```

项目库里的一张卡代表整个创作项目，封面只作预览。项目里的每张图是画布对象/结果，不各自生成一张项目卡。素材库里的一个条目仍可以是一张图片，但它提供跨项目复用，不承担项目历史。

### 4.1 名称规则（拟定实现，不调用语言模型）

1. 首次有效发送时，取第一段非空用户提示词，归一连续空白，按字素截取前 40 个字符，超长显示省略；完整原文保存在消息记录中。
2. 输入“生成一只猫”后项目即叫“生成一只猫”，不等模型完成，也不再显示 `Untitled`。
3. 用户手动重命名优先，后续聊天、结果回写和自动保存都不能覆盖它；用 `nameSource=prompt/manual/upload/fallback` 明确来源。
4. 只上传未发文字的项目，以首张上传文件名去扩展名命名；如随后发送第一段文字，仍是自动上传名称的可以改为提示词名。
5. 无内容的新建页显示“新建项目”，不立即向列表制造空白项目。首个有效上传、生成或画布编辑触发建立记录。
6. 旧的 `Untitled`/空名称优先从第一条有效 user 消息补齐；缺失则取已有上传名称，否则使用“未命名项目 · 日期”。无法恢复的历史不伪造；不把多个旧项目擅自合并。

### 4.2 生命周期与保存

- 第一次有效动作创建稳定 ID，创建请求有幂等键；同一次快速双击/网络重试不得建立多个项目。
- 创建成功后更新 URL 为当前项目，浏览器刷新、复制链接、后退/前进都能还原正确内容。沿用 `studio-v2?document=...`，无须为了路径像参考站而破坏旧链接。
- 已提交编辑立即进入本地持久化队列，云端约 800ms 防抖合并保存；指针移动过程仅更新渲染，松手才提交。800ms 是设计值，后续用体验与写入量校准。
- 本地草稿按用户与项目隔离；未创建的草稿使用独立 draft token，服务器返回 ID 后迁移。大量内容使用异步 IndexedDB，避免每次操作同步序列化整份大文档。
- 保存队列按项目串行，记录 local revision 与 server version。旧保存响应只能推进它对应的版本，不能把更新的草稿标成“已保存”。
- 项目切换前落本地日志；保存请求和结果绑定旧项目 ID。新项目建立独立加载/取消作用域，旧异步响应不得污染新画布。
- 双标签冲突保留本地副本，提供打开云端版/另存副本；不静默覆盖。保留现有乐观锁并把冲突状态做清楚。
- 展示“保存中 / 已保存 / 离线已保存在此设备 / 保存失败可重试”，不能把仅落 localStorage 说成已保存到云端。
- 模型任务不依赖页面存活。重开项目可恢复运行状态；结果以 job ID 唯一应用，图片加载重试不重新扣费、不重复追加。
- 图片解码失败保留原图与结果占位，允许单独重试加载。完成后追加结果、保持用户已有排布；用户正拖拽时不要强行跳镜头。
- 保存相机中心/缩放等视图偏好；视图偏好独立保存，不因一次平移改变项目内容版本或把项目顶到最近编辑榜首。

### 4.3 历史的容量和含义

“全部历史”分成项目内全部生成结果、任务/消息时间线、撤销历史三个概念。前两者应持久化且可分页；撤销可保留有限操作栈，不伪装成永久版本库。

现有 `messages.slice(-100)` 与 `appliedJobs.slice(-100)` 不足以支撑长期项目。迁移为可分页的消息/结果索引，任务结果应用建立唯一键，不能因旧 job ID 被截断而重复插图。画布对象先完成服务端分块/增量读取与可见区域加载，再扩大对象容量；达到约束时应明示，绝不丢掉最早的图。

项目历史列表、画布完整对象清单、任务结果列表共用同一归属关系。用户主动从画布移除某对象后，结果仍可从项目历史找回；本方案不把“全部保留”解释成用户永远不能删除画布对象。

### 4.4 项目库界面

- 用紧凑的“我的项目”标题和卡片网格替换大幅宣传标题。首张为新建卡，其余卡显示封面、提示词名称、时间和更多菜单。
- 封面按统一比例容器展示（建议 16:9，最终以同视口截图校准），避免各种原图比例使行高跳动；图像比例不变，裁切只作用于封面。
- 行内重命名：Enter 保存、Escape 取消、空名校验；保存后各入口同步更新。
- 搜索按项目名称匹配，键盘可直接使用；有清空、加载、无结果和失败状态。服务端分页，不局限前 100 个项目。
- 列表和顶部最近项目弹层共用查询/缓存，显示时间分组。新项目入口进入统一创作页，电商模式明确选择。
- 摘要接口仅返回 ID、标题、类型、封面预览、时间、数量等轻量字段，不返回完整画布 JSON。
- 默认封面取首张成功的完整场景图；以后可提供“设为封面”。封面更新策略确定后不能每次浏览随机变化。

## 5. 页面布局与动效实施规范

### 5.1 统一页面骨架

首页、项目库、素材库使用一致的顶部账户区、左侧紧凑导航、内容区域和弹层系统。工作台采用同一套视觉 token，但主内容是占满可用高度的画布，左侧聊天独立滚动，工具面板浮在目标旁或底部。

当前 `discover.css`、`creative-direction.css`、`studio.css` 不再继续末尾叠加互相覆盖的规则。建立统一颜色、字号、间距、圆角、描边、阴影、层级和动效变量；逐个替换页面容器。保留已有 React、Konva 与 Framer Motion，不为视觉重做而替换整个画布引擎。

内容型页面允许正常页面滚动；工作台只让聊天、菜单等需要的区域内部滚动。管理员页面同样采用固定可用高度、独立侧栏/主区域滚动，不能出现必须再滚动全局页面才能碰到导航底项的问题。

### 5.2 每个控件必须定义的状态

| 控件 | 状态与行为 |
|---|---|
| 导航 | 默认、hover、pressed、active、keyboard focus；文字说明可见；点击立即有路由反馈 |
| 项目/素材卡 | 固定占位、缩略图加载/失败、hover、更多菜单、重命名、选中；点击菜单不同时打开项目 |
| 输入框 | 空、聚焦、有内容、附件上传、发送中、失败保留输入；中文输入法 Enter 不误发 |
| 工具面板 | 进入、选择中、可提交、提交中、任务执行、成功、失败；取消只结束本次临时操作 |
| 弹层 | 锚点定位、屏幕边界避让、内部滚动、关闭与焦点归还、Esc；弹层内点击不透传画布 |
| 图片 | 预览占位、低清到高清、解码成功淡入、加载失败重试；透明背景与遮罩显示分开 |
| 长任务 | 提交反馈、排队、供应商运行、结果入库、图片加载，各阶段状态可区分；不显示虚假百分比 |

交互反馈优先使用 transform/opacity。大面积背景 blur 和全屏阴影限制范围；画布拖拽中不启动额外入场动画。尊重 `prefers-reduced-motion`，减少动画后功能、焦点与状态提示仍完整。

视觉验收同时对照默认、hover、按下、加载、错误和空状态截图，并录制页面/工具切换。仅一张静态截图相似不算动效验收。

### 5.3 画布右上角任务入口与任务列表（补充重点）

这是一块独立、持续可访问的任务 UI，不能用聊天里的文字、底部通知或侧栏“任务记录”替代。用户补充的两张截图明确要求对齐此处的运行卡片与完成卡片。

**截图确认的视觉结构：**右上角固定星光按钮；执行时按钮为彩色发光效果，展开内容位于其下方。深色大圆角任务卡左侧显示目标图缩略图及小加载指示，右侧显示工具名称、执行状态和相对时间。完成时显示大勾选图标与“任务完成”，入口呈中性深色状态。截图中的阴影/光晕只属于 UI，不进入生成图片。

**拟定行为：**

- 生图、抠图、物体移动、局部修改、扩图、拆层、视频等异步任务统一进入该列表；无需用户切到聊天或打开管理页才能查看进度。
- 提交立即创建临时任务卡，显示“正在提交”；服务端确认后绑定真实 job ID，随后区分排队、执行、加载结果、完成、失败、取消。提交失败保留原因与输入，不能留下永久转圈的假任务。
- 无输入图的文生图先显示稳定占位；有目标图的工具显示该图缩略图。每张卡对应一个任务，显示工具名称、当前状态和相对时间；多图任务保留总任务与各输出进度的明确关系。
- 入口可打开/收起列表；折叠不取消任务，展开不阻塞画布操作。并发任务能逐项查看，长列表内部滚动，浮层不超出视口。首次提交是否自动展开、何时收起，以补查参考站为准，不凭截图猜测。
- 全部当前任务成功并完成结果展示后，才显示“任务完成”汇总卡；仍有任务排队、运行或结果加载时不能提前显示。存在失败/取消时单独说明，不能用成功勾选掩盖。
- 完成结果自动追加画布，任务卡提供定位对应结果的能力。图片加载失败显示“生成完成，图片加载失败”，重试只加载结果；真实重新生成另建任务并明确计费。
- 默认以当前项目为任务范围，复用项目任务数据与恢复机制；切换项目后正确切换列表，旧任务继续运行且不串入新项目。参考站是否同时聚合跨项目任务待补查。
- 发光、加载、卡片进入/退出和完成勾选有连续的状态过渡；具体节奏需录屏核对。减少动态效果模式下仍用图标和文字清晰表明状态。

**实现落点：**从 `StudioWorkbench.jsx` 的现有 jobs/resultStates 提取统一任务状态与 `StudioTaskPopover` 展示组件（拟新增），复用 `/api/studio/jobs` 查询和取消能力，不再建立第二套轮询或另一份可能不同步的任务列表。任务完成、积分结算、结果入库和画布应用分别以已有服务端/客户端事实驱动。

### 6.1 物体移动的质量门槛

前端顺滑和模型结果正确是两套验收。使用用户的猫、书以及一个有明显接触阴影的案例，检查：原物体位置被合理补全、目标位置有且只有一个完整物体、没有残留前景/遮罩/黑块、背景主体和构图尽量保持、比例/旋转符合操作。

“没有阴影”不是删除一切真实光照。要消除的是旧位置残影、矩形预览阴影和贴图伪影；新位置合理的接触阴影应与场景一致。处理范围应包含旧物体关联区域，但不能粗暴清掉大面积背景。

本地交互不能等待分割/生成 API 才可拖动。服务端向所配云图像编辑模型传原图、明确源/目标区域、引导图与适配的 mask/指令；能力不匹配要提前提示管理员。不能从参考站效果断言它使用同一技术，更不能承诺任何一款生图模型都能稳定还原。

真实生成测试记录供应商配置版本、输入、源/目标几何、结果、各阶段耗时与人工评价。Mock/E2E 只证明流程和状态，不证明猫、书及残影质量。

### 6.2 导出不能用格式名代替能力

- PNG：透明背景正确；JPEG：背景合成可预期；WebP：尺寸/透明度/质量符合选择。
- PSD：在支持 PSD 的独立编辑器打开后能看到真实图层与正确位置，不能只是一个合成位图层却宣传图层工程。
- 内嵌位图 SVG：明确是包装图片的 SVG。
- 可编辑 SVG：只有真实文字、路径或矢量形状才能按对象编辑。任意照片要矢量化属于额外转换任务，需要独立服务、计费和效果验证；不能通过换扩展名伪装。
- 单图、选中对象、整个画布的导出范围需补查参考站后明确；先不猜参考站菜单的默认范围。导出不应把选框/遮罩/工具 UI 混入结果。

## 7. 素材、首页、电商和账户的完整范围

### 素材库

新增独立素材页及导航入口，复用 Asset 存储与所有权校验，增加用户素材条目/分类关系。项目里生成的每张图自动属于项目历史；只有明确“保存到素材库”时才成为跨项目素材条目，避免生成临时 mask、引导图也充满素材库。

提供上传、分类、未分类、搜索、选择、多选引用、回收站。参考站已看到 30 天保留提示，我们的素材条目也按此体验设计，但底层文件删除必须检查所有活跃引用：移入素材回收站不应破坏已经使用它的项目。30 天后清理条目不等于删除仍被项目/任务引用的文件。

项目删除与素材回收是两套状态。项目建议采用可恢复软删除以防误操作，这是本方案的产品建议，**不是已确认的参考站项目行为**；保留期与恢复 UI 需独立明确。项目删除后运行任务如何收尾、何时释放资产引用，在服务端事务/清理任务中处理。

### 首页与三种模式

- 首页保持创作入口和灵感内容的清楚层次，移除不匹配的巨幅英文 editorial 标题。模式切换只改变必要参数，不丢已填提示/附件。
- 对话用于上下文编辑和多步意图，快速用于直接任务。普通一次生图不强制进入“先计划再确认”的链路。
- 模型菜单按图片/视频等用户能力分组，用后台真实能力决定比例、分辨率、数量和费用。不能把参考站 UI 名称当成可调用的私有模型 ID。
- 固定 prompt、参考图、@ 与 *、数量/清晰度、费用说明纳入完整交互；发送失败保留输入和附件。
- 灵感卡片“做同款”回填自己的提示模板与授权参考，用户可改后提交。案例分类和内容需独立维护，不复制参考站案例资产。

### 电商套图

产品图、参考图、品牌、平台、国家、语言与商品说明对齐；延续现有 commerce 计划/分镜能力并复查与参考站的差异。语言模型继续由管理员指定，虽然参考站出现规划模型选择入口，本项目不把它暴露给普通用户。

套图任务、逐图失败恢复和最终结果归属同一个项目。输出保留原始商品事实，分镜与逐屏任务可追踪，不能依靠若干张随机图片冒充一套有产品一致性的详情页。真实套图效果和编辑流程在后续专项实测后补齐。

### 账户与服务界面

统一账户菜单、积分余额、使用/购买记录、充值入口、邀请、教程/帮助和错误反馈。复用现有账本和支付逻辑；参考站的价格、赠送/过期规则不是我们直接采用的商业规则。

使用记录可在弹窗中查看，表头清楚、内容内部滚动。水印设置、卡密、邀请细节及订单/发票功能先补查并核对本项目已有能力，再逐项进入开发清单；不能用外观相同但无业务支撑的入口充数。

| P2 画布交互 | 临时平移、缩放锚点、工具会话、聊天折叠、图像预览、右上角任务列表及运行/完成动效、自动追加与历史定位 | 猫/书操作全程无丢图/黑块/选区中断；低延迟输入与刷新恢复均通过；并发任务状态与画布结果一致 |
| P3 工具功能 | 局改/消除/扩图/移动面板、形状/宫格裁剪、文字编辑、分层、视频、导出 | 每个功能既验证 UI，又验证真实输出；未知子菜单先完成参考站补查 |
| P4 素材与模式 | 完整素材分类/回收、@/* 引用、快速多图、固定 prompt、模型能力与计费联动 | 同一素材跨项目复用不串改、不误删；直接操作一次提交，失败可恢复 |
| P5 全站补齐 | 电商深层流程、账户/记录/帮助、移动端、可访问性、剩余参考行为 | 差异清单无未解释项；所有未测项有实测证据或明确能力差异，不能标成已对齐 |

每阶段形成可部署提交，保持旧项目兼容；未完成能力通过真实能力开关显示，不摆可点但无效的按钮。用户确认进入开发后按上述阶段持续推进，不能只完成项目卡片就宣布整站复刻完成。

## 10. 性能与效果验收目标

以下是**拟定工程目标**，不是本次已测到的线上指标。参考站没有暴露后台时延，本轮也未完成压力测试。

| 场景 | 拟定目标与测量方式 |
|---|---|
| 点击/切模式/打开面板 | 本地视觉反馈 100ms 内；操作无网络依赖时不等后端响应才更新 UI |
| 平移/拖拽/选区 | 桌面 60Hz 设备目标接近 60fps；记录长帧及 >50ms 主线程任务；不在 pointermove 序列化全项目 |
| 项目列表 | 摘要不含 content；分页建议 24 项；常规网络下首屏可操作目标约 1s，冷缓存单独记录；缩略图渐进出现 |
| 列表封面 | 使用约 400–640px 预览，避免同时请求多张数 MB 原图；缓存命中率与传输大小进入测试报告 |
| 重开项目 | 先加载元信息/对象几何/可视预览，再后台补高清与历史；不等全部原图才允许平移 |
| 提交任务 | 立即显示提交状态；服务端持久化返回 job 后进入排队；保存/上传/队列/供应商/结果入库/解码分别记时 |
| 模型生成 | 不承诺秒出；按模型、分辨率、排队分别报告 P50/P95 与失败率；拖动预览的流畅度不依赖生成耗时 |
| 长项目 | 以 100 个项目列表、150 个画布对象和超过 100 条消息/任务验收分页/不丢失；再逐级增加负载，记录设备内存 |
| 减少动态效果 | 开启 reduced-motion 后所有操作完整，无必须等动画完成才能点的步骤 |

外部模型并发能力与服务器承载能力分开测。CPU 配置不决定上游模型配额；不以界面顺滑推断可同时支持几千个生成任务。

## 11. 必须通过的验收场景

1. 首次发“生成一只猫”，项目立即使用该名称；未等生成结束刷新也有同一个项目和任务。
2. 中文、多段、emoji、超长提示词命名不乱码；只截标题，不截断保存的用户消息。
3. 手动改名后再生成、自动保存、刷新，名称不被第一提示覆盖。
4. 空白打开关闭不增加空项目；同一次创建重试不产生重复卡片。
5. 上传→生成→物体移动→局部修改，原图与每次输出都在同一个画布，项目库只有一张对应卡。
6. 重开项目恢复聊天、历史结果、布局和视图；超过 100 条的早期结果仍可查，不被 slice 丢掉。
7. 同时打开 A/B 项目，异步任务晚返回、快速切换与浏览器后退都不把结果加错项目。
8. 网络断开后编辑有本地持久化和明确状态；恢复网络可同步；双标签冲突不静默覆盖。
9. 项目列表搜索有结果/无结果、翻页、重命名、更多菜单均工作；新建不固定误入电商。
10. 所有列表封面使用预览图；慢网/图片损坏有占位，不导致布局塌陷。
11. 框选猫后按 Space/中键/平移按钮移动视野，再返回继续拖动目标，选区与工具不丢。
12. 输入框内正常打空格及中文输入法 Enter 不触发画布平移或误发送。
13. 移动猫/书的真实结果为完整场景：旧位置修复、新位置正确、无残影和预览黑块，原图保留。
14. 移动目标缩放/旋转/靠近边界时，指示与提交几何一致；不支持的越界操作有明确反馈。
15. 局改/消除笔刷大小、重置、区域遮罩、平移恢复和取消均正确；未选区域不能误提交。
16. 直接生图与工具操作只提交一次，连点/重试不重复扣费；成功但图片加载失败仅重载图片。
17. 扩图不同长宽比、抠图透明边缘、拆层坐标/组、文字编辑和视频播放分别有真实输出验收。
18. 形状裁剪 alpha 正确；宫格拖动交点后，每块导出范围和画布预览一致。
19. @ 引用项目图片、* 选素材、附件移除、固定 prompt、模式切换均不丢输入；引用身份与显示一致。
20. 素材分类/未分类/搜索/回收/恢复完整；删除素材库条目不会破坏已引用项目。
21. PNG/JPEG/WebP、PSD、两种 SVG 在独立软件中打开检查尺寸、透明度、层/矢量可编辑性，不只检查文件后缀。
22. 桌面 1440×960 与 1920×1080 对照布局及逐状态截图；窄桌面、390px 手机宽度检查菜单避让和触控。
23. 动画记录包含 hover、按下、切页、开关弹层、图片加载；快速连点不会残留遮罩、丢焦点或造成点击无响应。
24. 电商、账户、使用记录和管理员页分别检验内部滚动、顶部/侧栏完整可达；长列表不用额外全局滚动寻找按钮。
25. 同时运行生图与抠图，右上角入口正确提示执行中，列表显示各自缩略图/占位、名称、状态和时间；收起再展开、刷新与切换项目后仍正确恢复，未全部结束不显示“任务完成”。
26. 任务列表覆盖提交失败、模型失败、取消、生成成功但图片加载失败、全部成功五种结果；完成态视觉与截图对照，结果自动落画布且可定位，重试加载不重新生成或扣费。

验证层次：对持久化/并发/几何/计费写必要单元和集成测试；核心用户路径 E2E；相同视口的视觉对照与交互录像；部署后的真实模型验收。纯样式微调不写镜像实现的无价值测试，但必须目视验证。

## 12. 开发前后继续补查的明确清单

当前已足够确定项目与界面基础改造方案，但以下不能标成“已研究透/已复刻”：

- 参考站的新建项目时机、所有自动命名边界、项目删除恢复、跨设备保存与双标签冲突。
- 有真实素材后的批量操作、移动分类、回收恢复与跨项目引用行为。
- 超清与反推子菜单、文字编辑、图层拆分、视频实际参数和运行结果。
- 批量选择、右键菜单、快捷键全表、手机触控及响应式布局。
- 导出作用范围、PSD 层结构、可编辑 SVG 转换机制和费用。
- 电商 Agent 的完整生成/修改/交付流程，快速模式的真实并行和任务管理。
- 右上角任务列表的触发/自动展开收起规则、多个任务排序、跨项目范围、完成态停留时间及完整动效节奏；当前已有用户截图证据，不能再遗漏这一独立 UI。
- 购买记录、邀请、水印、卡密、发票等深层页；不靠账户菜单上的名称猜实现。

下一开发阶段对照清单补查，再实现对应模块。每个条目最终用“交互已验收 / 输出已验收 / 尚有差异”标记，避免用一个“1:1 完成”掩盖未验证的功能。
