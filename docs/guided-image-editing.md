# 局部修改与扩图：区域指示图流程

## 范围与依据

参考 2026-10-17 保存的椒图发布版前端：局部修改发送绿色标记主图、参考图与用户要求；扩图把原图放进目标大小的绿色画布，再发送目标比例。前端接收完整结果图。公开代码不能确认其服务端模型、内部提示词或后处理。

按用户最新要求，这两项不添加语言模型调用或自动优化开关，不增加积分费用。原有对话区手动优化入口继续独立工作。智能消除、文字擦除、物体移动等其他工具保留原执行路径。

## 实现

- `edit-geometry.js`：扩图预设使用整数比例计算容纳原图的目标框，受单边 1024、边长 8192、面积 40 MP 的现有上限约束。不可用的比例禁用，不通过裁剪或畸变强行适配。无需增加的方向允许为零。手机端同样显示比例预设和目标像素尺寸。
- `guided-edit.js`：保留未标记原图，额外生成纯绿色区域指示图。扩图指示图表达原图的确切位置及新增区域；局部修改指示图表达用户涂抹的选区。相较椒图的单张标记主图，本实现额外保留未遮挡的源图供模型识别被编辑对象。
- 指令明确规定第一张为待编辑图、第二张为区域指示、后续为用户参考，要求返回完整画面。删除任务明确要求自然补背景，禁止以模糊、涂抹或遮盖代替删除；扩图要求保持主体位置、比例、透视及景深，不复制边缘物体。
- OpenAI 兼容编辑接口还接收对应 alpha mask；方舟与 DashScope 直接使用区域指示图，避免适配器再次追加另一种颜色的标记图。DashScope 最多三张总输入，因此局部修改最多接受一张用户参考图，前后端同时限制。
- 输出比例由实际编辑画布决定，对话输入框的尺寸只提供分辨率档位。方舟最低使用 2K；旧官方 GPT Image 1 和旧 Qwen Edit 使用适配尺寸并等比加边。提交前进行供应商尺寸验证。
- 结果通过画框还原后完整交付，不再将原图中央硬贴回新结果，也不对不匹配的比例执行 `fit: fill`。比例偏差超过画框校验容差会失败；扩图新增区域仍明显透明也会失败。原图作为独立图层保留。
- 成功任务的 `resultData.edit` 保存原始要求、实际发送的指令、目标尺寸和模型请求尺寸，方便管理员对照任务排查。没有额外模型请求或自动付费重试。

## 验证与边界

自动测试覆盖比例计算、绿色选区编码、原图不变、返回整图而非中央回贴、异常比例拒绝、透明扩图失败、供应商输入差异、原有工具回归、结果持久化及一次计费。数据库集成测试明确断言没有语言模型调用。浏览器测试覆盖桌面和手机端的比例选择与提交。

本地当前没有启用的供应商通道，测试中的模型返回来自可控 fixture；这些结果不能证明真实模型的花盆删除、纹理补全或主体一致性已经达到椒图水平。完整结果模式靠模型遵循保留要求，不承诺未编辑区域像素完全一致。

上线后用原花盆图圈定完整花盆并输入“删除花盆，用周围植被自然补全”，再用老虎图测试左右扩至 16:9。对照原图检查残留花盆、人工模糊块、重复尾巴、主体比例、矩形接缝，以及异常输出是否保留原图并释放预留积分。保留具体任务 ID 和供应商模型名以便继续调优。
