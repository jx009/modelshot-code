# 登录、邀请与积分充值改造

## 实施顺序

1. 修复无用户会话仍被识别为登录成功的问题；明确 30 天会话、定时与页面切换刷新，登录成功后从服务端确认会话再跳转。账号封禁、密码重置仍即时撤销会话。
2. 邀请码统一为六位大写字母和数字；数据库锁和唯一约束防撞码；旧邀请码转换后保留别名，已分享链接继续有效。
3. 后台系统设置增加 Google 登录显示开关和注册送积分。邮箱和 Google 新用户使用相同的注册奖励逻辑，生成独立积分流水，不追补老用户。
4. 复用 LetAiCodeWeb2/backend/src/services/epay.service.ts 的易支付 submit.php 表单、MD5 排序签名协议及支付宝/微信渠道；适配本项目的订单快照、事务、幂等入账与分销佣金。后台可配置网关、商户、加密密钥、渠道、公开回调域名及支付开关；保留 Stripe。
5. 后台动态管理固定积分包：名称、说明、人民币和美元价格、积分数量、排序、推荐、上下架。积分无有效期，无订阅；旧订阅只保留账务兼容。价格用最小货币单位存储，支付只能使用服务器订单快照。
6. 全局充值弹窗：导航与画布点击积分直接打开，含精选积分卡片、支付方式、余额、订单到账状态及账单入口；中文实际以 CNY 下单，英文以 USD 下单。/pricing 复用同一套充值界面。
7. 验证会话撤销/刷新、邀请码别名/碰撞、注册送积分、支付验签/金额/币种/重复回调、套餐修改后的订单快照、后台与手机弹窗；构建后提交并推送。

## 支付边界

- 浏览器回跳仅展示订单状态，不能触发积分到账。只有验签通过且商户、订单、金额、币种、渠道匹配的异步通知能入账。
- 易支付使用 CNY；USD 使用 Stripe；未配置可用支付渠道时明确提示，不假装支付成功。
- 密钥加密保存且不返回前端。配置和套餐变更使用现有 ROOT 权限与管理审计。
- 不复制参考项目的周期套餐、有效期和模型额度转换体系。

## 管理员使用

- `/zh/admin/settings`：在「新用户注册」填写注册赠送积分（0～1000000）；仅影响此后创建的账号，不追补老账号。在 Google OAuth 区选择显示或隐藏登录入口后保存；关闭会同时停用该登录渠道。
- `/zh/admin/billing`：配置开放充值、易支付开关、网关根地址、PID、商户密钥、本站公网地址以及支付渠道；可动态添加、删除、排序、推荐和上下架最多 12 个固定积分套餐。每个套餐分别填写人民币价格、美元价格及到账积分，无订阅和有效期。
- 保存要求 ROOT 权限和操作原因，密钥加密保存、不会以明文返回浏览器；商户密钥输入留空表示保留原值。
- 易支付的商户信息取自支付平台后台，网关地址填写根地址，不附加 `submit.php`。本站公网地址填写实际可访问域名或地址，不带查询参数。创建订单时自动生成异步通知 `/api/payment/epay/callback` 和回跳 `/api/payment/epay/return`，不用逐个订单手填。
- 中文页面展示并实际支付人民币，易支付提供支付宝、微信等渠道；英文页面以美元下单，使用 Stripe。Stripe 的 Secret Key 和 Webhook Secret 仍在系统设置配置，回调使用项目原有 `/api/webhooks/stripe`。
- 开关、注册赠送积分和套餐每次读数据库，保存后下次请求即生效；凭据最多缓存 60 秒。待支付订单使用创建时的价格和积分快照，套餐修改不改变旧订单。更换商户、密钥前需先处理原商户的待结算订单。
- 点击首页、侧栏、用户菜单或画布余额，直接打开充值弹窗；充值记录在账户页。支付回跳后查询本人订单，验签通知确认后刷新余额。

## 上线步骤与会话配置

1. 拉取代码并安装依赖，执行 `npx prisma generate` 和 `npx prisma migrate deploy`，新增邀请码别名表后再构建、重启应用。
2. 保持生产 `NEXTAUTH_SECRET` 稳定，多个应用实例必须使用同一个值；`NEXTAUTH_URL` 设置为用户实际访问的公网地址。HTTP 与 HTTPS、IP 与域名之间的 Cookie 不共享，应统一对外访问地址。反向代理/CDN 不得缓存 `/api/auth/*`；接口自身也已设置 `private, no-store`。
3. ROOT 配置支付和套餐，再用商户测试订单核对金额、通知、积分流水和余额。此次本地测试使用隔离数据库和签名回调，没有向真实商户扣款。

会话有效期 30 天，页面导航、重新聚焦和联网时从服务端刷新。短暂空会话可以通过新的服务端请求恢复；不会从本地缓存伪造登录。账号封禁、密码重置或会话版本变更仍撤销登录，此时重新登录可直接建立新会话，无需清缓存。

## 验证记录

- 单元测试覆盖会话版本、封禁、数据库连接短暂失败重试、Google 开关与 30 天期限。
- 集成测试覆盖邀请码碰撞/旧别名、注册奖励、订单快照、CNY/USD 分账、支付验签、金额/商户/渠道校验、并发重复回调以及退款边界。
- 浏览器使用真实凭据登录与数据库验证刷新、切页、撤销后重新登录；ROOT 动态配置套餐和 Google 开关，经 HTTP 创建易支付订单并重复发送签名回调，检查仅一次入账。桌面与手机均通过。
- 弹窗另检验深浅色、手机滚动与常驻关闭/支付按钮、空会话恢复、确认到账后余额刷新，以及英文美元和隐藏 Google。
- 兼容当前 HTTP/IP 访问环境：发起充值、新增套餐复用 `requestKey()` 的随机数降级；浏览器禁用 `crypto.randomUUID()` 后仍能创建请求，网络失败重试沿用同一幂等键。最终充值界面 7 项、登录与支付 HTTP 回归 8 项通过。
