# 原生 Office 导出：实现与边界

更新：2026-10-24。状态：原生 XLSX 与 DOCX 初期链路已实现并通过定向单元测试，默认不开启。不是完整 Excel/Word 兼容，也不是浏览器、数据库或 Office 客户端验收结果。

## 为什么新增转换器

旧 `exports/docx.js`、`exports/xlsx.js` 接受 schemaVersion=1 的业务简化结构。Univer 1.2.0 完整快照是 schemaVersion=2，不能先压回业务结构再导出，否则会丢失编辑器新增内容。

当前安装包未发现可直接调用的完整 Office 转换器。新增 `src/lib/creation/exports/native-xlsx.js`，直接把允许的原生结构写入 SpreadsheetML；`native-docx-model.js`、`native-docx-style.js`、`native-docx.js` 直接解析原生文档并生成 WordprocessingML。两者均用既有 JSZip 打包，没有引入新依赖。运行代码不导入 Univer 引擎或公式计算器，也不经过 schemaVersion=1 结构。

## 固定版本与执行链

1. 原生表格中点击“导出”才加载弹窗、查询记录；点击“保存并导出”才 flush。单元格未按 Enter 确认或 IME 未结束时拒绝提交。导出请求本地日志保存固定 revision，响应丢失后重放相同版本，不把之后的编辑混入旧请求。
2. Office 导出请求先校验作品归属。由于 `ArtifactRevision` 没有 schemaVersion 列，`export-source.js` 在事务外读取指定 revision 的不可变私有 blob：限制 2 MiB、10 秒、流式累计字节和 SHA-256 校验。根据文件内 schema/kind/engine/version 选择转换器，不能信任客户端提示或当前作品最新格式。
3. 入队事务再次校验所有权、revision ID 与 checksum。指纹继续包含用户、revision、checksum、格式和 exporterVersion。旧记录重放先于新准入；明确重试仍受 Worker/开关/队列上限约束。没有新增数据库字段或迁移。
4. 新转换器版本 `univer-sheet-xlsx-1` / `univer-document-docx-1`、心跳键 `univer-xlsx` / `univer-docx`，与旧转换器分开。仅旧转换器的心跳不满足原生请求。`CREATION_NATIVE_OFFICE_ENABLED=true` 加 `CREATION_NATIVE_XLSX_EXPORT_ENABLED=true` 或 `CREATION_NATIVE_DOCX_EXPORT_ENABLED=true` 联合控制对应新准入，默认关闭。旧 `CREATION_XLSX_EXPORT_ENABLED` / `CREATION_DOCX_EXPORT_ENABLED` 不会顺带开放新转换器。
5. Worker 根据已入库 exporterVersion 读取固定原生 revision，并复核 schema/kind。转换参数带 exporterVersion，子进程再次匹配实际输入。源码格式、完整性及不支持功能属于确定失败，不进入临时失败的重复重试循环。
6. 继续使用隔离导出进程：Worker 并发 1、子进程 256 MiB JS heap、转换 120 秒、无数据库/对象存储/模型凭证、输出 64 MiB 上限。文件校验、租约、取消、归属复核与私有下载复用原链路。进程参数不等于原生内存/CPU/磁盘硬隔离，部署仍需要独立受限容器或机器。

列表的新导出开关按当前作品格式显示；每条失败/取消记录另外按自己的 exporterVersion 返回 canRetry，历史格式仍开放时可以明确重试，即使当前格式尚未开放。真正请求仍读取指定历史文件。已完成下载不因新准入关闭消失。

## 原生 XLSX 已覆盖

| 内容 | 当前处理 |
| --- | --- |
| 工作簿 | 工作表顺序、名称、隐藏/深度隐藏、1900/1904 日期系统；至少一张可见表 |
| 单元格 | 稀疏值、数字、布尔、普通/强制字符串；以 `=` 开头的普通字符串不变为公式 |
| 样式 | 引用或内联单元格样式；字体/字号、粗斜体、有限下划线/删除线、实色文字/填充、四边框、对齐、换行、缩小字体、文本方向/旋转、数值格式 |
| 行列 | 行高、自动高度当前结果、列宽、行列隐藏；像素转点/Excel 列宽单位 |
| 合并 | 非重叠矩形合并；覆盖非锚点值/公式时拒绝，避免 Excel 丢弃内容 |
| 视图 | 从起始行列冻结、缩放、网格显隐、左右方向、标签颜色；滚动位置不是导出内容 |
| 公式 | 基础算术/比较、SUM/AVERAGE/MIN/MAX/COUNT/IF/LOOKUP 的限定语法；保留公式，不计算，移除可能过期的缓存并要求 Excel/WPS 重算 |
| XML | 转义特殊字符、保留 CR/LF/Tab、转义 SpreadsheetML `_xHHHH_` 字面量；非法 XML 控制字符/坏代理项拒绝 |

公式只有聚合/LOOKUP 向量参数允许区域，区域算术和 IF 返回区域不支持；共享、数组、外部工作簿、命名/未知函数及迭代计算拒绝。跨表引用必须存在。循环/完整依赖图及 Excel 运行成本没有证明，导出主机不运行公式。

字体不嵌入，列宽按 7 像素数字宽度换算，Office 排版不承诺与网页像素一致。缓存清除后的预览结果取决于打开软件是否重算。

## XLSX 明确拒绝，而非静默删除

- 富文本单元格、图表、绘图、背景图片、条件格式、批注、超链接资源等未适配对象。
- 非空保护规则、命名范围、主题等插件数据；允许列表内的空核心插件记录可以通过。
- 工作簿/工作表默认样式、整行/整列样式继承尚未转换。
- 非零文字内边距、clip 策略、主题色/透明色、斜边框、独立装饰线颜色及其他没有明确映射的样式。
- 未知非空字段/自定义扩展、非法坐标/数值、不可表示的冻结结构。

内部 ModelShot 的 adapterVersion/sheetId/cellId 仅用于业务标识，不写入 XLSX；其他自定义数据拒绝。未引用的样式不是导出作品内容。存储层继续保留全部合法原稿；导出失败不修改原文件，也不自动创建“已删除高级内容”的副本。

## 原生 DOCX 已覆盖

直接解析原生 dataStream，保留 UTF-16 位置、格式片段、段落元数据和表格层级，不先转成业务 blocks。单次遍历内容，元数据先建索引，格式游标递增；没有每个字符遍历全部格式或图片列表。

| 内容 | 当前处理 |
| --- | --- |
| 正文 | 原文、中文/emoji、Tab、段落、手动分页/分栏；引擎 renderedPageBreaks 作为软分页提示，不能误变成手动分页 |
| 字体 | 原生字号/字体族/东亚字体、粗斜体、下划线、删除线、前景/背景色、上下标、隐藏文字、大小写显示、语言及字距阈值等已适配字段；保留明确关闭格式 |
| 段落 | 原生内置标题样式、标题级别、对齐、行距/段距、缩进、keepNext/keepLines、孤行控制、分页前、Tab stop；段落标记格式不污染正文 |
| 列表 | 最多九层，数字/字母/罗马/项目符号、起始值、独立 listId；同一层中途重启需后续适配，当前明确拒绝 |
| 表格 | 原生矩形及有界嵌套结构、列宽、行高、重复表头、边框/底色、单元格边距/垂直对齐；合并表格单元格暂拒绝 |
| 图片 | 私有归属检查、校验下载、子进程解码后的 PNG/JPEG 行内图片、尺寸、标题/描述；不把资产 API URL 写进文件 |
| 链接 | 安全的 HTTP/HTTPS/mailto 外部链接；每个正文/页眉/页脚独立关系文件，保留链接文本样式模式；默认蓝色与下划线以 1.2.0 默认主题映射 |
| 页眉页脚 | 默认/首页/偶数页引用和相应内容；PAGE/NUMPAGES 安全字段，Word 打开时更新 |
| 分节 | 页面尺寸/方向/边距继承、分节类型、页码默认连续/显式重新起始；未覆盖的复杂分节参数拒绝 |

本轮核对真实核心模型，兼容其自动补入的断词配置。docStyle 页码起始值只用于第一节，后续节只有显式指定才重置；缓存分节转换结果，避免前瞻与真正消费同一 metadata 时重复计数。

原生自定义命名 styleId/sId 的继承、非空 note/word-style 插件、批注、脚注、修订、原始 DOCX XML、SDT、浮动/裁剪/旋转图片、合并单元格、外层列组、复杂列表重启等仍明确拒绝。原生内置标题与直接样式已支持，不应把“自定义命名样式尚未支持”误解为不能导出标题。

几何像素换算成 Word twips/EMU，字体/段距保持原始点单位。字体不嵌入、半点字号与边框单位需舍入，不承诺与浏览器分页一致。导出成功只说明该原生结构通过转换，并不证明完整 Word 兼容。

## 资源预算

- 沿用原生快照 2 MiB、20 张表、10 万稀疏单元格、深度/JSON 节点上限。
- 全工作簿最多 10 万输出行记录、4096 种实际使用样式、1 万公式、12.8 万公式字符、10 万引用单元格面积。
- 合并校验全工作簿最多展开 10 万坐标，使用集合检测重叠；不会按声明的百万行网格整体展开。
- 样式 ID 缓存、稀疏行列输出；没有网页端 ZIP、Office 转换或公式计算工作。

这些是实现中的限制，不是吞吐、主线程、冷启动或真实内存实测。

DOCX 另限制：全部正文/页眉/页脚合计 50 万 UTF-16 单元、2 万段落、10 万 inline 片段、1 万表格单元格、8 层嵌套、最多 32 个页眉页脚 story、200 个列表定义/1000 个列表实例、每个 part 1 万关系、累计生成 run XML 32 MiB。解析阶段先拒绝异常 token、格式片段越界/切断代理项、缺失或重复锚点，再生成 ZIP。表格/图片资源属于原始快照，未消费的这类对象会使导出失败，不能在成功文件中无声消失。

## 验证与下一步

本轮 9 个定向文件、59 个不同用例最终通过，17 个触及代码/测试文件 ESLint 通过。定向测试覆盖：真实 Univer core `model.save()`、ZIP/XML 解码、内容/样式/维度/合并/日期系统、字面公式、缓存清理、拒绝路径、源文件流式完整性、固定历史版本、Worker 版本/开关、确定失败不重试、实际导出子进程，以及真实 React/controller/session 的输入确认/flush/恢复接线。网络、数据库和浏览器引擎部分使用替身。

导出弹窗也修复了 React Activity 隐藏/恢复时的旧 busy 状态：每个活动生命周期重新建 gate，旧提交或取消返回不能更新新实例的状态、清理日志或解锁新请求。

原生 DOCX 本轮追加验证：11 个定向文件、78 个不同用例通过，14 个触及代码/测试文件 ESLint 通过。包括真实核心模型快照、结构/样式/页码/软分页、受控 AI 改写后变长位置的导出、真实子进程图片解码、独立准入与固定版本归属、原生 UI 保存后 DOCX 提交、既有 XLSX/语义 DOCX 回归。没有实际浏览器、Office 客户端、真实数据库或队列验收。

仍需补齐更多原生 DOCX/XLSX 特性、Office 导入、浏览器/WPS/Excel 打开验收和性能基线对比，再评估开放新开关。本轮未启动服务/数据库/队列 Worker，未运行构建、Prisma 生成或迁移，未部署或开启功能。
