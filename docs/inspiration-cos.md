# 灵感发现的 COS 持久存储

启用管理台已有的腾讯 COS 配置后，无需单独上传案例图片。部署后首次访问首页/灵感页的 `/api/inspiration` 会在响应结束后，为全部已发布案例创建同步任务；直接访问案例详情也会触发整批同步。默认案例和管理员引用的站内图片都包含在内。

## 加载流程

1. 首次访问先用原来的图片地址，页面不等待整批上传。
2. 现有 worker 的独立图片同步队列将原图和保留比例的 640px WebP 缩略图上传到 `${prefix}/inspiration/v1/`。
3. 两个对象都保存成功后才写入持久化完成记录。并发 worker 通过数据库锁避免重复上传，失败由队列重试。
4. 列表在同步期间每 5 秒刷新元数据，自动切换为 COS 缩略图；后续访问直接得到 COS 地址。详情使用 COS 原图。图片请求绕过美国的 Next.js 图片优化接口。

完成记录保存在 SystemConfig 的 `inspiration_cos_v1:` 命名空间，不修改管理员编辑的案例配置，也无需数据库迁移。键根据 COS 目标、案例 ID 和源图内容确定；重启、重新部署、不同用户访问不会重新上传已完成的相同图片。更换封面或 COS 目标后会补传。

## 存储与访问权限

- 对象永久保留，应用没有为灵感对象设置 TTL，也不会随版本部署清理。COS 存储桶自身的生命周期规则仍然有效，请勿给此目录配置到期删除。
- 沿用私有存储桶和短期签名链接，不要求公开整个存储桶。过期的是访问链接，不是图片。元数据请求仍由应用处理；图片字节由浏览器直接从 COS 下载。
- 已公开案例下架后，不再签发其访问链接；已签发链接在有效期结束前仍可访问，对象继续保留。
- COS 禁用、尚未同步或图片加载失败时保留原始图片回退路径。

## 部署与核对

同时更新 web 和 worker 镜像，保持现有 Redis、worker 服务正常运行。确认管理台 COS 已启用且连接测试通过，然后打开首页触发同步。

在浏览器网络面板查看 `/api/inspiration`：同步完成的条目会包含 `imageUrl` 和 `thumbnailUrl`，且 `deliveryPending` 为 false。列表图片请求应直接访问 COS 域名的 `640.webp`，不再访问美国的 `/_next/image`。COS 控制台中能看到 `inspiration/v1/` 下的原图和缩略图。

失败时查看 worker 的 `COS_MIRROR_RETRY` 以及 web 的 `INSPIRATION_COS_ENQUEUE_DEFERRED` 日志。队列自动重试；重试耗尽后，后续访问可以在下一个 10 分钟任务窗口重新入队。不会为了重试删除已有对象。
