# 页面加载与请求等待

## 本次改动的范围

- `api()` 的 GET 请求默认在 15 秒后取消，截止时间覆盖响应头和 JSON 响应体。调用方取消仍保留原有取消语义，计时器和监听器在请求结束后清理。
- 写入请求默认不新增截止时间、不自动重试。上传、生成和 SSE 原有专用流程不变；需要长时间等待的 GET 可以显式传入 `timeoutMs: 0`，或指定其他毫秒值。
- 读取超时的错误码为 `REQUEST_TIMEOUT`。超时不代表服务器一定停止处理；不得据此盲目重放写入、扣费或生成请求。
- 灵感库使用同一读取截止时间；刷新失败保留已有内容，展示失败状态和重试入口，继续使用原有刷新间隔。
- 会话恢复只针对本次挂载期间已经确认登录、随后变成未登录的情况。正常匿名首次访问不再额外探测；恢复最多四次且不重叠。NextAuth 原有焦点刷新和定期刷新保留，不从本地存储恢复身份或权限。
- 模型配置将数据库路由、价格配置和工具服务查询并行执行。工具服务仍有两秒截止时间，故障时不宣告不可用工具可用。未缓存价格、权限或密钥；工具查询很慢时，首次请求仍可能等到该截止时间，本次不是完全拆分接口。
- 导航普通再次点击不再变成整页重载。八秒后仅显示“页面仍在加载”，提供独立的“重新打开页面”链接；用户主动选择该链接时才进行整页导航。

## 发布与验证

用户私有图片仍以 MinIO 为主存储，COS 为异步私有副本，不在生成成功前等待跨区同步：

- 素材列表、分页项目封面、项目详情及分页图层/消息历史，在响应中批量附带已就绪副本的短期签名。查询同时限制资产归属、有效状态及当前 COS 目标，并校验副本键；不逐图查询、不向 COS 发起 HEAD。单次最多处理 256 个不同资产，超出或未就绪的仍可走原有授权图片接口。
- 含签名的接口显式使用 `private, no-store`。客户端 `api()` 在返回业务数据前移除分发字段，仅按当前登录用户保存在有上限的内存映射中；退出、换号或旧请求返回时不会复用另一会话的直链，不把签名写进项目内容或本地草稿。
- 预览组件和画布加载器共用分发解析：有有效签名时直达 COS，接近过期时回到原有 `delivery=auto` 授权接口获取新链接；实际加载失败只回退一次到 `delivery=proxy` 的 MinIO 源图，不无限重试。画布继续用原始资产 URL 作为去重键，并保留 CORS、取消和并发限制。未携带批量签名的旧接口也可经 `auto` 使用 COS。
- COS 同步顺序调整为 320、640、1280 预览，最后原图；已上传成功的副本在重试时跳过。桶必须保持私有，并配置允许站点来源的图片读取 CORS，否则组件回退源站。

以上是代码改动，随应用及 worker 镜像正常发布后生效，不会自动修改现有线上服务或 COS 配置。

应用改动随正常镜像发布生效，无需在小服务器上安装依赖或构建。公开图片的香港同步和 Nginx 一次性配置见 `docs/hong-kong-static-deployment.md`。

在有足够资源的 CI 中运行针对性的 Vitest 用例：`client-api.test.mjs`、`session-refresh.test.jsx`、`navigation-link.test.jsx`、`capabilities-parallel.test.mjs`。公开图片发布的纯文件测试为 `tests/deployment/test_prepare_hk_static.py`。这些测试不替代线上源站证书、Nginx 配置和网络连通性验证。

COS 私有图改动的针对性用例为 `asset-delivery.test.mjs`、`asset-image.test.jsx`、`cos-delivery.test.mjs`、`image-loading.test.mjs`；可在 CI 使用 `npm run test:unit -- tests/unit/asset-delivery.test.mjs tests/unit/asset-image.test.jsx tests/unit/cos-delivery.test.mjs tests/unit/image-loading.test.mjs` 运行。

上述改动减少不必要请求、串行等待和异常等待体验，不证明或修复香港回源握手超时、上游断连的具体根因。已有耗时日志仍用于对照故障时的连接、首字节及完整响应时间。
