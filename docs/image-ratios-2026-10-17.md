# 生图比例与分辨率补齐

根据用户提供的参考站截图，首页、画布、电商整套参数和逐场景编辑改为共用 `ImageSizePicker`。面板采用四列比例网格、形状图标、选中高亮及分辨率分段按钮；适配深浅主题、窄屏、键盘焦点与原生dialog内部弹层。

比例：智能、1:1、2:3、3:2、3:4、4:3、9:16、16:9、21:9、1:4、1:8、4:1、4:5、5:4、8:1。分辨率：1K、2K、4K。

## 请求和保存

- `src/lib/studio/image-size.js` 是唯一比例、分辨率、兼容尺寸白名单。新选项保存为 `16:9@2K` 等标识，旧 `1024x1024` / `1024x1536` / `1536x1024` 继续原样执行。
- 首页批量提交、画布直接生成/参考编辑和多步骤计划均携带所选size。电商整套和单张覆盖共用相同白名单；`/api/commerce/plan` 和任务创建、云端文档均接受新选项。
- 调整分辨率纳入画布批次指纹，避免失败后更换尺寸却复用旧批次幂等键。尚无结果图层的已保存云项目，也可以保存参数修改。
- 案例与旧文档不会因为增加比例选项自动改变原尺寸或自动重新生成。

## 实际尺寸语义

本项目的智能比例：有参考原图时跟随原图比例，无参考图时使用1:1；不会宣称已经获得参考站未知的自动构图算法。

K为方形等效像素档位，基准边长1024/2048/4096，根据宽高比计算宽高并按16像素对齐。资产最大单边8192，因此极长宽图会同比缩小；智能原图比例限制在1:8到8:1。面板显示实际请求像素尺寸。1K的2:3/3:2保留既有1024×1536/1536×1024尺寸，兼容已有通道。

例如：16:9 / 2K → 2736×1536；1:4 / 2K → 1024×4096；8:1 / 4K → 8192×1024。它们是传给供应商的尺寸，不是生成后拉伸小图伪装高分辨率。

局部蒙版修复、物体移动等工具仍按原图范围合成、保留原尺寸；画布生图设置不会强行改变这些工具的输出画幅。

## 供应商适配

- OpenAI兼容生成JSON、编辑multipart：将选择解析为实际 `widthxheight`，不发送自定义标识给供应商。
- 百炼原生接口：将实际尺寸转换为 `width*height`。
- 火山方舟：显式分辨率保持所选实际尺寸。原有保存请求的隐式2K升级保留兼容；新1K请求低于现有适配器3686400像素下限时提前报错，提示选2K/4K。
- 不支持显式size的旧 `qwen-image-edit`、已知仅支持固定尺寸的官方模型按协议提前拒绝。未知兼容网关由其实际返回判定，不能保证所有渠道支持全部组合。
- 任务创建前检查已知不支持的尺寸，拒绝时不冻结积分。最终执行也检查一次，供应商拒绝沿用原有失败结算。各分辨率当前沿用通道/工具配置单价，未实现按分辨率分档计费，上线需按实际供应商成本设置渠道。

## 验证

单元测试覆盖45种新组合、旧尺寸兼容、智能比例、尺寸上限、非法值、供应商JSON/multipart实际尺寸与已知限制；数据库集成测试覆盖尺寸保存和失败不占积分。浏览器测试覆盖桌面/手机网格全部选项、4K提交、画布参数刷新恢复、首页一次回车、原生电商弹窗中逐场景选择与配方复制。未调用真实付费模型，不能将协议验证等同于真实4K画质验收。
