# Cheso 对标：剩余开发与交付方案

更新：2026-10-25。范围：当前工作区剩余开发；本文件只制定方案，不表示以下功能已经实现或验收。

**本方案纠正此前海报/PPT 路线，优先于旧方案中冲突的技术决定。** 新海报采用 HTML/CSS 源文档与 DOM 编辑；新 PPT 采用每页完整 HTML 的 VPPT 类文档。撤掉当前新增的固定海报模板入口，不继续扩充模板库。旧对象 JSON 作品保留可打开、编辑和导出能力，不能因路线调整损坏已有数据。

最终范围不缩减：保留现有图片画布、电商 Agent、视频；完成海报生成与修改、服务端多步 Agent、PPT、文档、表格、网页。用户承担大范围联调，开发方仍负责补齐源码、必要的定向验证、配置说明与可用的交付入口。

## 1. 现在还差什么

| 模块 | 可以沿用的当前代码 | 必须补齐的开发 |
|---|---|---|
| 海报 | 项目/文件/版本、模型配图、素材权限、保存冲突、任务与账本 | 撤掉固定模板；HTML 生成、DOM 编辑、整页/选区 AI 修改、HTML 对应的真实导出和视觉检查 |
| PPT | 大纲、逐页任务、页面管理、备注/隐藏、演示框架 | 改为逐页 HTML；共享主题/母版、可编辑表格/图表、HTML 导出链、PPTX 可编辑导入 |
| Agent | Run/Step、队列、重试/取消/预算、结果发布、Outbox/事件流 | 跨类型工具规划、输入输出依赖、审批与恢复、旧浏览器计划衔接、真实后台运行验证 |

| 表格 | 生成、Univer 网格、计算 Worker、选区 AI、XLSX 导出 | XLSX 可编辑导入/往返、大表分批生成、图表/保护/富文本及复杂公式处理 |

| 页面与性能 | 全高工作台、紧凑输入、按需属性栏、延迟编辑器、局部工具侧栏 | 逐屏对照 Cheso，压缩仍浪费的空间；旧站与新模块同条件性能基线和回归证据 |

这些不是“再测一下就完了”。海报/PPT 的路线替换、Office 导入、网页发布、跨类型规划都包含实质开发。数据库、队列、计费、生产性能的真实环境验证另列，不能把两类缺项混为一谈。

## 2. 对标依据与实施边界

### 2.1 已确认的 Cheso 形态

- 海报 `.vimg` 是 HTML 文本，带 `vimg-width`、`vimg-height` 元数据；前端通过 HTML 编辑器处理文字、图片、形状、选择、拖拽及层级，保存完整页面 HTML。
- 海报/HTML/PPT 局部 AI 请求带当前页完整 HTML、选中 HTML 或文字、作品版本和附件，返回 `edited_html`。这条路径不要求从固定版式中选择一个模板。
- `.vppt` 是 JSON 容器，`pages[].html` 为完整页面 HTML，另有主题、大纲、备注、隐藏状态、`templates`、`mind_flow` 等字段。默认页面 1280×720。
- PPT、海报与网页有共享 HTML 编辑基础；隔离预览与编辑采用不同路径。网页运行预览使用独立来源 shell。
- DOCX/XLSX 存在原始文件和编辑投影、保留 OOXML 的处理路径，不能仅用简化对象重建文件后宣称保真。

依据：[海报研究 §3.5](../../rea/investigations/cheso-2026-10-24/chapters/03-image-poster-video.md)、[编辑器研究 §04.2–04.3 及 Office 章节](../../rea/investigations/cheso-2026-10-24/chapters/04-editors-assets-collaboration.md)。上述主要是公开前端代码与协议证据，海报生成全流程没有线上成功样本；不能把它写成已获得 Cheso 后端源码。

### 2.2 本项目的明确决定

1. 对标用户看到的创作形态、编辑能力、页面布局和结果质量；复用本项目后端和账本，不照搬接口名称。
2. 新海报不再使用固定对象 schema 限制模型排版；不提供当前那套固定模板作为核心生成方式。
3. PPT 的共享主题/母版仍要做。它用于统一整份演示稿，与强制用户套固定海报模板是不同需求。
4. 当前对象编辑器仅承担历史作品兼容；禁止将任意新 HTML 强制降成现有有限文字/图片/形状 JSON。
5. Cheso 未确认的闭源提示词、布局算法和转换引擎由本项目实现，不冒充逆向所得。PSD 分层等尚未验证的能力不列为已支持。

## 3. 第一优先：共享 HTML 创作内核

海报、PPT、网页共用基础能力，但使用独立产品适配器；不把所有逻辑塞入 `StudioWorkbench` 或一个巨型编辑组件。

### 3.1 源文档、编辑投影与保存

新增版本化格式分发：`legacy-layout`、`html-poster`、`html-slides`、现有 Office 和 website。由文件元数据决定加载哪个编辑器，旧文件没有新标记时保持原路径。

拟定核心接口如下，这是待实现契约，不是 Cheso 服务端源码：

```ts
type HtmlPage = {
  id: string;
  html: string;             // 权威源文档，不保存宿主临时注入内容
  width: number;
  height: number | 'auto';
};
type EditContext = {
  fileId: string;
  baseVersion: number;
  pageId: string;
  selection?: { nodeIds: string[]; fingerprints: string[] };
};
interface HtmlEditorAdapter {
  flush(): Promise<{ page: HtmlPage; dirty: boolean }>;
  getSelection(): Promise<EditContext['selection']>;
  applyRevision(page: HtmlPage, expectedVersion: number): Promise<void>;
  dispose(): void;
}
```

- HTML/CSS 是权威数据。编辑页由源文档构造受控投影；注入的选择框、bridge、临时 URL、测量样式不进入保存结果。
- 图片引用保存稳定素材身份或受控资源路径；显示时解析成授权 URL。禁止持久化即将过期的签名地址、Blob URL 或宿主内部地址。
- 首次规范化为可编辑节点建立稳定 ID；复制时重新分配，移动时保留。保存保留正常样式、结构和未知元数据。
- 编辑支持定位布局及常见 flex/grid；拖拽按布局语义调整。不能通过把整页绝对定位重建，悄悄破坏原网页响应式结构。
- 对暂不支持直接操作的复杂布局，保留原始源码并提供源码/AI 修改；界面明确当前选中项的可用操作。

### 3.2 预览与 DOM 编辑

- 编辑投影禁用作品脚本；可信编辑 bridge 操作 DOM，承担文本、图片、样式、拖拽、多选、对齐、分组、层级、撤销/重做。
- 可执行预览放到无主站 Cookie 的独立来源，资源和访问权限独立约束。主站同源不运行用户生成的任意脚本。
- 消息校验来源、窗口、协议版本、请求 ID、消息大小与字段；请求有超时、取消和卸载清理。项目切换后旧回包不得覆盖新作品。
- 预览执行后的任意 DOM 不自动回写源文档；返回编辑模式仍以已保存源文档为准，避免脚本执行副作用污染作品。
- 复用已有 `web-preview`、资源解析、源码 Worker 中可用部分；现有预览会去除脚本，不能直接当作完整 HTML 编辑器或 JS 运行环境。

### 3.3 AI 修改与并发保存

1. 发送前 flush，取得确定版本；提交当前页完整 HTML、选区片段/文字、指令和附件身份。
2. 服务端校验用户、项目、文件、版本、素材、大小和预算，沿用持久化语言任务。
3. 返回完整 HTML，经解析、资源白名单、节点/内容体积和布局检查后才进入候选版本。
4. 选区修改必须检查选区外结构、文字和样式差异；涉及共享 CSS 时同时计算其他元素影响。越界结果不能无提示覆盖全页，可拒绝重试或让用户明确选择扩大修改范围。
5. 发布使用 CAS。用户在生成期间继续修改时保留双方结果，生成副本或提供明确的差异确认；不静默覆盖，也不重复调用已收费模型。
6. AI 应用前建历史点；撤销、重做、刷新恢复和版本回看必须可用。

### 3.4 内核验收

同一份复杂 HTML 样本依次完成：打开、文字/图片/布局修改、撤销、保存重开、选区 AI、冲突处理、导出。校验没有资源失效、宿主标记污染、跨页面误改和编辑后样式丢失。至少覆盖定位排版、flex、grid、长文本、中文字体、私有图片。

## 4. 海报：先交付一条完整可用链路

### 要补的功能

- 首页选海报，输入需求、尺寸、风格与参考资料；不出现生图专属分辨率/数量参数，不要求选择固定模板。
- 后台流程为需求整理 → 可选素材生成/选择 → HTML/CSS 排版 → 检查 → 发布可编辑海报。没有配图需求时不强行生图。
- 模型生成真正的页面内容、文字层级和版式；图片模型负责图片素材。用户文字保留为 DOM 文本，不能整张海报只剩一张不可编辑图片。
- 直接编辑标题、日期、正文、字体、颜色、图片、裁切、大小、旋转、层级、对齐与分组；增加/删除文字、图形、图片。
- 对话既可修改整页，也可限定选区；引用选区时显示引用对象与范围。
- 检查文字溢出、越界、资源加载、空白页、尺寸和可读性；自动修复有次数/费用上限，失败展示可继续修改的作品和具体问题。
- 保存、历史、复制、重命名、导出使用统一文件体系。

### 导出必须同步改造

现有 Skia 对象渲染器不能代替任意 HTML 渲染。新增独立 HTML 转换执行器，以固定浏览器/字体版本加载固定作品版本，等待字体和图片就绪后生成 PNG/JPEG/PDF；SVG 保留为需单独确认的格式能力，不宣称任意 HTML 能无损转 SVG。

浏览器转换不进入 Next 请求进程或轻量调度 Worker；初始并发 1，设置总时限、页面/资源体积和进程内存限制，结束回收。导出资源通过受限素材解析器提供，不开放任意内网抓取。

### 退出条件

提供三类非固定模板作品：纯文字活动海报、带商品/照片海报、复杂图文海报。每类均演示“需求 → 生成 → 直接编辑 → 选区 AI → 保存刷新 → 图片/PDF 导出”。验收重点是版式自由度、文字可编辑、局部修改边界、成品质量；不能拿模板切换截图充数。

## 5. PPT：逐页 HTML、共享主题、实际可编辑导入导出

### 格式与生成

- 新格式使用 `metadata + pages[] + templates + mind_flow` 的容器；每页有稳定 ID、完整 HTML、大纲、备注、隐藏状态。保存保留未知字段，重排只改变顺序和页码。
- 大纲确认后逐页后台生成，完成一页即可查看；失败只重试该页，不重做整份。
- 主题维护字体、色板、间距、页眉页脚、页码和公共样式；主题更新可批量应用，保留用户明确覆盖的局部设置。
- 共享母版有独立身份与版本，页面引用母版并支持局部覆盖；不能只复制样式后就称为共享母版。
- 增删、复制、排序、隐藏、备注、单页/选区 AI、新增页、全屏演示接入共享 HTML 编辑器。
- 表格保留单元格/样式/合并关系，图表保留数据与图表配置；能够修改数据并重新渲染。

### PPTX 导入与导出

- 二进制 PPTX 与 HTML 幻灯片是不同格式，建立独立导入适配器；保存原始文件，提取主题、页面、文字、图片、形状、表格、图表及关系。
- 第一批就用真实中文 PPTX 小样验证转换，不把格式研究拖到最后；不支持的对象保留原件，标出编辑限制，防止无提示丢失。
- HTML → PPTX 需要新转换映射。文字、图片、形状、表格、图表按各自语义转换成可编辑对象；阴影、渐变和复杂 CSS 分别记录兼容程度。
- 全页截图导出只能作为明确标记的外观降级选项，不能计入“可编辑 PPTX”完成项。导出带有降级清单。
- PDF/演示截图复用 HTML 浏览器转换；现有 JSON→PPTX 路径继续服务历史文件。

### 退出条件

10 页生成演示稿和 30 页性能样本；跨页主题修改不破坏局部覆盖，单页重试与排序不串备注。可编辑文本/表格/图表在 PowerPoint/WPS 中验证；导入后编辑再导出，记录保真和不支持项。复杂任意 PPTX 无损不作无证据承诺。

## 6. 文档与表格：补齐导入、保真与大内容能力

### 6.1 文档

- DOCX 上传后建立原始 OOXML 包与编辑投影，不再只提取文字作为参考资料。
- 导入正文、段落/字符样式、列表、表格、图片、链接、分页、页眉页脚；建立原 XML 与编辑节点映射。
- 直接编辑或 AI 修改只更新对应范围；未修改的部件、关系和未知扩展原样保留。
- 对批注、修订、域、目录、文本框等逐项建立支持矩阵。无法可靠编辑的结构受保护或只读，保存前说明限制，不能静默删除。
- AI 修改保留选区外内容；脏输入、版本冲突、取消与重开纳入保存协调。
- 保留现有 DOCX/Markdown/PDF；PDF 的实际分页和编辑器视图差异须明确。中文字体、复制/搜索、Linux 渲染继续验证。

### 6.2 表格

- XLSX 导入原包与 Univer 投影，保留工作表身份、单元格类型、公式、数字格式、合并、行列尺寸、冻结、筛选、名称与外链信息。
- 回写基于原包，局部修改不能把其他工作表、图表、关系或保护信息丢掉。
- 大表生成按工作表/有界区域拆成步骤，结果分块持久化；UI 只接收摘要与当前可视区域，不逐 token 重建整个工作簿。
- 公式计算继续放 Worker，限制计算量/时间，支持取消与循环引用报告；导入时不自动触发无限范围重算或外部连接。
- 图表保留数据区域和配置；保护、富文本和复杂公式逐项实现范围修改。暂不支持的功能保留原数据，并清晰报告能力。
- 导出后在 Excel/WPS 验证公式、数字精度、日期、合并、图表与保护；不能只检查 ZIP 能解压。

### 6.3 共用导入要求与验收

解析/解压放受限子进程或专用 Worker；限制原文件、解压总量、条目数量、关系深度和处理时长。保留私有素材权限，不主动执行宏或访问外部关系。

每种格式交付：简单文件、带图片/表格文件、含复杂特性文件；完成“上传 → 可编辑 → 局部 AI → 导出 → Office 重开”。复杂样本必须说明保留、可改、只读和不支持项，不能把范围说明替代已承诺的基础导入开发。

## 7. 网页：真实交互预览与静态发布

- 多文件项目使用稳定相对路径，支持 HTML/CSS/JS/图片；源码、可视编辑、对话修改写入同一文件版本体系。
- JS 预览接入独立来源运行环境；多页跳转、按钮交互、样式与资源路径能实际运行。无 JS 的静态预览继续保留为快速路径。
- 发布创建不可变快照，包含文件清单、内容校验和、资源引用与入口；生成独立发布地址。
- 数据上传完整后再原子切换站点发布指针；失败不替换上一成功版本。
- 撤回停止公开访问；回滚切回历史快照，编辑中的草稿不被覆盖。清理须考虑历史/发布版本引用，不能删掉仍在访问的资源。
- 公开发布只放用户确认公开的资源；私有项目附件和带签名的主站地址不能直接泄露到发布包。
- ZIP 与发布使用一致的路径重写规则，深层页面刷新和多页相对链接需可用。

退出条件：生成一个有图片、多页和 JS 交互的网站，修改后发布第二版，实际访问、撤回、回滚均成功，第一版资源仍可恢复。本轮是静态站点托管；需要自定义服务端/数据库的全栈应用不伪装成已运行。

## 8. 多步 Agent：跨类型任务真正离开浏览器运行

现有 Run/Step 和发布/账本底座保留，不推倒重做。补齐的是跨格式工具与持续执行闭环。

### 工具与调度

- 工具注册表声明输入/输出 schema、文件类型、读写范围、价格/预算、是否有外部副作用、超时和幂等策略。
- 至少接入：资料读取、图片生成、海报生成/修改、PPT 大纲/单页/组装、文档/表格创建与修改、网页文件编辑、导出。
- 规划器产出受校验的步骤依赖图；依赖使用产物 ID/固定版本/结果引用，不把全部正文塞进每一步。
- 调度器负责 ready → running → completed/failed/awaiting-input，语言/图片/转换在各自队列执行；有界重规划，禁止无限自我循环。
- 用户改需求、缺少资料、预算不足时进入等待状态；确认后继续，成功步骤不重复执行。
- 发布网页、覆盖重要文件等副作用有单独确认点；普通生成与编辑不增加无意义的反复确认。

### 恢复、取消、计费与旧任务

- 关闭浏览器后步骤仍由服务端推进；重开通过持久事件序号和文件版本恢复，浏览器只观察、提交消息和用户操作。
- 重复提交、队列重投、上传成功响应丢失、发布冲突不重复出文件或扣费；未知付费调用结果先对账，不自动再付费请求。
- 取消后停止新步骤；迟到结果按账本和结果状态收敛，不把已取消任务继续发布成成功。
- 旧画布计划按版本区分执行所有权。可迁移的未开始步骤原子交接；已经由浏览器执行的步骤先确认状态，不能两端同时推进。不可安全迁移的在途计划明确保留原路径，新建计划走服务端。

退出条件：一条“读资料 → 海报 → 配套 PPT → 导出”任务，关页仍能完成；中途失败仅重试失败步骤；确认、取消、重启恢复、计费幂等有证据。语言模型自由规划必须限制在已注册工具，不能用伪成功状态代替缺失工具。

## 9. 页面整改：作品优先，逐屏对照

保留目前有效的密度改动，继续以 Cheso 同类页面截图作对照；不是只改一张首页。

| 场景 | 页面要求 |
|---|---|
| 首页 | AI 创作/电商 Agent，类型按钮、素材、输入、开始创作；不同类型只展示相应参数 |
| 创作工作台 | 利用剩余视口全高全宽，左对话右作品，顶部只保留标题/保存/版本/导出等必要操作 |
| 对话 | 短输入保持约 48px，随内容增长但上限约 132px；附件/参数/提示默认收起；历史占剩余空间 |
| 海报 | 画面按剩余区域适配，属性栏按选择打开；不放固定模板大卡片挤占作品 |
| PPT | 窄缩略图栏＋当前页，备注/属性按需打开；对话可折叠，折叠不卸载编辑器或丢草稿 |
| 文档/表格 | 使用编辑器主区域，避免再套多层标题、内边距、固定宽卡片；工具保持紧凑 |
| 网页 | 文件树/属性可折叠，预览有真实目标 CSS 视口并缩放；不能因父容器宽度改变作品布局 |
| 旧图片画布 | 图片与画布主导；局部修改工具侧停靠、可收起，画布适配扣除实际面板面积，避免挡住目标图片 |
| 移动端/低高度 | 对话与作品切换，工具折叠；输入、底部动作和滚动区均可达，不靠全屏固定大面板遮住作品 |

对照视口：1920×1080、1440×900、1024×768、390×844，另覆盖 1440×720。宽屏顶部单行、无空的外层卡片边距；关闭对话/属性后作品应实际扩展。拖动分栏只更新尺寸，不重建编辑器。

每屏提供整改前后同视口截图；同时验证保存状态、滚动、键盘焦点、工具打开/收起、文件切换和未保存保护。不得用静态截图证明真实生成链路可用。

## 10. 性能：沿用近期修复，设硬门槛

以下为待测验收预算，不是当前实测成绩。基线必须包含当前工作区的有效优化，并记录 Git HEAD、工作区快照、设备/浏览器/服务端配置、数据规模和测量方法；不能只与数日前干净提交比较。

### 前端预算

- 首页不加载 Univer、HTML 编辑器、PPT、转换器等专用代码；网络记录与 bundle 分析确认。新旧项目列表共用缓存、账号隔离和在途合并，不恢复全站 eager prefetch。
- 点击/输入/选择的宿主可见反馈 p95 目标 ≤100ms；编辑/选择的局部动作不触发整棵工作台、完整文档或聊天列表重渲染。
- 连续拖拽目标约 50–60fps；低配验收设备低于 45fps 或出现新增 >200ms 主线程长任务时定位处理，不能用只显示骨架掩盖交互卡顿。
- PPT 30 页只挂载当前编辑页；缩略图使用缓存图片和虚拟列表，初始渲染并发 1，按测量增加。历史预览、关闭属性栏及时释放资源。
- 对话增量事件合并，正文与 Office 大对象不放全局 React 状态；自动保存按脏范围/版本节流，不能每次鼠标移动写整份文件。
- 10 次打开/切换/关闭后，iframe、Worker、事件订阅和计时器数量回到稳定值；GC 后堆内存不随轮次持续增长。记录峰值及残留对象。

### 服务端预算

- 轻量调度不运行浏览器、长公式或 OOXML 重转换；CPU 密集处理使用独立进程/队列，有明确并发、超时和资源限制。
- HTML 转换初始并发 1；不沿用其他队列较高并发。Office 导入/导出串行起步，基于机器实测决定是否扩容。
- 每用户活跃任务/模型调用、总排队量、资源大小、页数、步骤数、重试次数有上限。不得无界 Promise.all 抓图、渲染、生成全部页面。
- 数据库读元数据/当前页，文件正文放对象存储；事件/日志/缩略图有保留与清理策略。不能每条事件都读整个作品或全量会话。
- 保留图片/电商/支付队列资源预算；新增队列名不能代替实际资源隔离。记录 CPU、RSS、DB/Redis 连接和等待时间。

### 回归门槛与规模样本

同条件至少重复 5 次，记录中位数/p95；旧首页、项目列表、画布拖拽、局部修改、电商任务提交，关键指标相对基线恶化超过 10% 必须定位，不能直接宣布完成。明显卡顿或资源泄漏即使未超过该比例也需处理。

新模块覆盖：复杂 HTML 海报、30 页 PPT、长文档、大工作簿、含多资源网页。表格按总非空单元格和公式密度分别测，首轮目标为 5 表/10 万非空单元格；这只是待验证规模，不能先写成已支持。单次本机开发模式结果不能替代生产环境结论，模型远程生成耗时单列。

## 13. 验证与用户联调交接

每项分别记录四个状态：源码已实现、定向验证通过、真实服务验证通过、生产/兼容验收通过。替身接口只证明交互和状态处理；本机转换只证明对应样本和平台；两者都不能标成全链路上线可用。

开发方交付给用户的联调包必须包含：

1. 功能入口与可复现用例，样本输入/预期产物；新旧格式与数据兼容说明。
2. 迁移与 Prisma 生成顺序、环境变量/功能开关、Worker 命令、独立预览域名/存储配置、转换镜像和字体要求；每项写明当前是否已执行。
3. 按实际机器给出的 Worker 并发与资源配置；队列积压、超时、账本异常、对象残留如何观察和恢复。
4. 真实环境需验证：关页继续、Worker 重启、Redis 断连/乱序、重复消息、取消迟到结果、模型响应丢失、付费对账、发布撤回/回滚。
5. Office/WPS/Linux 字体与中文 PDF 检查清单，实际支持矩阵、降级报告、已知问题和样本链接。
6. 同条件性能数据与旧功能回归结果；回滚开关停止新准入，已付费作业仍能恢复结果发布。已生成作品不能因关闭入口而无法访问。

本次方案不执行迁移、启动新 Worker、调用付费模型、生产构建或部署。实施时优先使用已获许可的定向单测和本地页面验证，遵守小机器串行校验约束。需要真实环境的步骤列明依赖和命令后交接；尚缺源码必须先补齐，不能转写为用户联调任务。

**整体交付标准：六项能力各自形成可用闭环，海报/PPT 的形态与 Cheso 对齐，页面以作品为主体，旧画布/电商/视频没有明显性能和功能回退。任何一项只有入口、固定样板、替身截图或未连接的底层代码，都不算该项完成。**
