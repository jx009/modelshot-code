# COS 对象路径与固定 CDN 地址

## 数据格式

普通用户图片上传（工作台、电商和素材上传）单文件上限为 50 MiB（界面显示 50 MB，52,428,800 字节），前端、代理上传和 COS 直传共用 `src/lib/image-upload-limits.js`。超过上限会被拒绝，仍保留 4000 万像素、图片格式与现有处理并发限制；代理路径转换为 PNG 后也必须满足大小上限。公告二维码、选区蒙版和供应商接口的独立限制不随之放宽。上传入口的各层反向代理需允许大于 50 MiB 的请求体（multipart 有额外开销，可保留现有 `client_max_body_size 128m`）。这项调整不需要数据库迁移。

新 COS 原图的 `Asset.objectKey` 保存对象路径，例如：

```text
letaidraw/originals/cmty2jcum000001nyj11arz4x/original/b6043b7f-2abb-44b8-acc6-0980318e5ec9_studio_0.png
```

普通图片展示地址在返回时拼接：

```text
https://ai-cdn.iamshuaidi.com/letaidraw/originals/cmty2jcum000001nyj11arz4x/original/b6043b7f-2abb-44b8-acc6-0980318e5ec9_studio_0.png
```

域名集中在 `src/lib/asset-cdn.js`。数据库不保存临时签名、过期时间或 CDN 查询参数。缩略图回执继续保存对象路径；灵感图和公告二维码使用现有版本/标识推导对象路径，不需要重传已存在的对象。

原有 `cos://桶名/地域/对象路径` 记录保持兼容，不做批量迁移。原有 MinIO 对象继续使用原存储读取，副本准备好后再走 CDN。COS 原图使用专用的 `${prefix}/originals/` 命名空间，上传暂存使用 `${prefix}/uploads/pending/`，不要将 MinIO 对象放进这两个保留命名空间。

纯路径对应当前配置的 COS 桶；存在 COS 原图或待清理直传记录时，管理台禁止直接更换桶/地域，避免路径被误解释到另一个桶。修改配置时不要绕过该检查。读取旧 `cos://` 记录时仍校验桶与地域。

## 分发与权限

自由画布提供独立的“本地上传”和“素材库”入口；添加参考图也可直接从电脑选择。画布支持粘贴剪贴板图片，创作描述框内粘贴图片会添加为参考图并保留描述文字；普通文字粘贴、其他文本编辑框与弹窗不被画布上传拦截。本地选择、拖入和图片粘贴复用同一上传链路与 50 MB 校验，批量上传仍串行执行。

- COS 桶保持私有；上传 PUT、服务端读写和删除继续使用原有鉴权。
- 用户图片 API、后台素材 API 继续检查用户或管理员权限。但返回的 CDN 链接无签名，拿到地址即可访问；应用权限不保护已经发出的 CDN 链接。
- 不在读取链接里携带 COS SecretId 或签名参数。服务器内部读取流仍可使用短签名，这不是浏览器展示链接。
- 附件下载继续经过鉴权 API，保留下载文件名与 `Content-Disposition`；不以公开图片地址代替下载响应。
- 图片显示失败时，现有用户图片/灵感图片组件保留源站代理回退。不要把该回退当作 CDN 配置正确的证明。
- 批量分发元数据保留一天的客户端刷新窗口；它不是 CDN URL 的有效期。公开灵感元数据可以持久缓存固定 CDN 地址，不再随五分钟签名到期丢弃图片地址。
- 新上传/复制图片写入 `Cache-Control: public, max-age=86400`。旧对象头不会被自动重写；CDN 的实际缓存行为还取决于 CDN 控制台配置。
- 删除文件、隐藏作品或退出登录不会立即清除 CDN/浏览器缓存。需要撤销公开访问时，删除源对象并刷新 CDN 缓存；已下载的内容无法撤回。

## 部署前配置

1. 将 `ai-cdn.iamshuaidi.com` 配置为 HTTPS CDN 加速域名，源站指向当前 COS 桶；保留完整对象路径，不额外增加或去掉 `letaidraw/`。
2. 配置私有桶回源鉴权。浏览器访问不要要求 COS 签名或额外 URL 签名，否则固定地址会返回 403。
3. CDN 仅允许对外读取需要公开展示的图片目录；不要开放 `${prefix}/uploads/pending/` 暂存目录、桶列举或写入。
4. 配置 CDN 的 CORS 响应头，允许本站来源 GET/HEAD，暴露 `ETag, Content-Length, Content-Range`。画布读取需要 CORS，仅能显示图片还不够。若按 Origin 动态返回响应头，缓存规则也要正确区分来源。
5. 设置图片缓存规则，尤其检查旧对象的 `private` 缓存头。不要缓存 403/404 错误；不要对依赖原文件字节的地址启用内容改写。
6. 浏览器 PUT 仍走 COS 官方端点，使用独立的签名和 COS CORS 设置，不经过 CDN。
7. 同步部署 web 和 worker。新代码支持旧记录，但旧 worker 不能识别新纯路径，因此不能先产生新记录再长期保留旧 worker。回滚也需要兼容新格式，不能直接回滚到只认识 `cos://` 的版本。

## 轻量人工验收

- 上传一张新图，检查数据库 `objectKey` 是纯对象路径；浏览器展示地址应为固定 CDN 域名且没有 `q-sign-*` 参数。
- 打开一张旧 COS 图片和一张尚未镜像的 MinIO 图片，确认兼容与回退。
- 检查原图、缩略图、灵感图、公告二维码和后台图片预览；测试画布读取及附件下载。
- 用管理台“测试连接与跨域”分别检查 COS 读写和 CDN 图片解码；此操作会执行远程读写，不在本轮静态校验中自动运行。
- 本轮不执行数据库迁移、构建、测试或生产配置变更；此格式调整本身不新增数据库字段。
