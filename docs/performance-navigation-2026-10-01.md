# 模块切换性能排查（2026-10-01）

## 实测范围与结果

使用生产构建，通过 Chromium 实际点击导航并等待目标模块根节点可见。
线上测量地址为 `http://152.53.36.159:5000/zh`，使用未登录的新浏览器上下文；没有提交生成任务。

| 切换目标 | 当前线上 | 本地生产构建 |
| --- | ---: | ---: |
| 首页 → 电商套图 | 1397 ms | 112 ms |
| 电商 → 我的项目 | 853 ms | 70 ms |
| 我的项目 → 自由画布 | 1364 ms | 150 ms |

上述结果为单次诊断样本，不是 P95 或并发容量数据。两端版本、网络和服务环境不同，不应把差值直接当作代码优化收益。
本次线上访问记录到的首页 JavaScript 长任务为 52 ms，三个模块切换未新增超过 50 ms 的长任务。
独立 HTTP 请求测得连接约 275–283 ms、首字节约 567–614 ms；浏览器新上下文首页首字节约 1350 ms。
这支持继续优先改善资源等待和网络往返，不能据此排除登录后数据库、素材加载或大项目画布的性能问题。

## 代码问题与修复

- `15132ff` 已拆离客户端不需要的 Zod / 服务端校验依赖，缩小了页面依赖。
- 原主导航使用 `prefetch="auto"`，动态路由在点击前未取回完整页面；普通卡片禁用了预取。
- 新的 `NavigationLink` 默认按访问意图预取：鼠标进入或键盘聚焦时启用完整预取，避免所有可见卡片一起抢占连接；显式 `prefetch={false}` 仍保持关闭。
- 为语言路由增加轻量、适配主题的 loading 边界，路由结构已取回而页面仍在等待时显示骨架。路由结构尚未返回时，由既有导航状态提示反馈。

## 同环境前后对比

本地生产服务器，Chromium CDP 模拟 280 ms 网络延迟、512000 bytes/s 上下行；每组使用新的浏览器页面。
鼠标悬停组在点击前悬停 1200 ms，时间从点击开始计算，包含 Playwright 点击和页面可见性检查。

| 场景：进入电商套图 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 直接点击 | 889 ms | 890 ms |
| 提前悬停入口 | 841 ms | 74 ms |

请求记录确认修改后的完整页面请求在点击前发出。悬停不会消除下载耗时，而是将下载提前；直接点击仍需等待网络。
自动回归分别检查鼠标悬停和键盘聚焦、点击后复用已完成的请求，以及页面响应被阻塞时的加载状态。

## 验证边界

本地 UI 测试使用接口 fixtures，不需要数据库或模型凭据。线上这次没有登录状态，因此未验证私有项目数据加载、后台接口耗时或服务器负载。
发布本次修改后，仍需在实际登录账户和已有大项目上复测；不能用这里的本地数字承诺所有页面固定耗时。
