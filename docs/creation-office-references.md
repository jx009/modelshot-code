# Office 创作参考资料：实现与验收边界

更新：2026-10-24。状态：代码与限定测试完成，默认关闭，尚未通过真实后台/模型/Office 客户端验收。实现属于本项目，不代表已获得 Cheso 私有后端代码。

## 用户用途

用户可以把品牌说明 DOCX、预算 XLSX、已有方案 PPTX 加到创作对话中。后台提取其中的文字和数据，供海报、PPT、文档、表格或网页任务参考。移除引用只改变本次请求，不删除已上传文件；可以再次引用并下载原文件。

这是**参考资料读取**，不是把任意 Office 文件直接变成右侧可编辑作品。原始二进制保持不变，上传时不转成简化文档。现有 Univer 编辑、选区 AI 和原生导出是另一条链路；完整 Office 导入仍未交付。

## 支持范围

| 格式 | 模型可读取的信息 | 明确限制 |
| --- | --- | --- |
| TXT / MD / CSV | 严格 UTF-8 文本 | CSV 作为文本，不推算类型或公式 |
| DOCX | 正文段落、表格单元格文字、插入修订文字；段落/表格定位 | 排除删除修订；不读取页眉页脚、脚注批注、公式或图片；定位不是渲染页码 |
| XLSX | 实际工作表顺序/名称/隐藏状态、日期系统、稀疏单元格地址、原始值、共享/内联富文本内容、公式字符串及已有缓存值 | 不计算公式；缓存明确标记未经验证，可能过期；不应用数字/日期显示格式，不解释图表或图片 |
| PPTX | presentation 顺序的页面文字、隐藏页标记、讲者备注 | 对象顺序未必是视觉阅读顺序；不读取母版/布局文字、图表数据或图片；备注可能包含页码占位文字 |

读取器支持已适配的 transitional/strict OOXML 命名空间。仅有工作表名、幻灯片状态等元数据而没有可读文字/值/公式时，返回 `CREATION_REFERENCE_NO_TEXT`，不会把空资料当作已读内容。超限返回明确错误，不静默截断后继续生成。

不支持 PDF、旧版 DOC/XLS/PPT、加密/密码文件、ZIP64/分卷、宏/ActiveX/OLE 嵌入、OCR、完整样式和版面复原。没有外链抓取、宏执行或公式求值。

## 执行链路

1. `ReferenceFiles.jsx` 根据会话接口的 `officeEnabled` 展示允许格式。前端只校验类型/大小，串行上传，保留下载入口和已上传列表；不加载 ZIP/XML 读取器。
2. `POST /api/creation/sessions/[id]/references` 验证身份、同源、请求大小和频率。领域层先验证会话归属，再读有限字节、检查签名、计算 SHA-256，将原文件写入私有存储。
3. 会话锁内再次核对归属、累计大小和数量，创建 `CreationReference`。沿用已有数据表，本次未新增迁移。
4. 新任务、重试以及每个新付费步骤，在创建任务/预留积分前检查引用归属和 Office 读取服务准入。已提交任务的幂等重放不再次准入；已成功结果的发布恢复不依赖附件仍可读，也不二次调用模型。
5. 语言 Worker 在持久化模型提交标记之前读取引用。逐文件校验存储字节数/校验和；Office 交给独立子进程，结果携带文件 ID、名称、格式、原文件校验和、读取版本及支持限制。
6. 模型提示词把资料标为不可信来源数据，要求尊重来源定位和读取限制，尤其不能把公式缓存当作重算结果。解析失败时不写模型提交标记、不调用模型，沿用既有任务失败与积分结算路径。
7. 下载路由重新验证用户/会话/项目归属和文件完整性，返回 attachment、`private, no-store`、`nosniff`，中文名使用 RFC 5987。不会把私有对象键或签名存储 URL 发给浏览器。

## 性能与隔离

| 项目 | 限制 |
| --- | --- |
| 文本文件 | 256 KiB/文件 |
| Office 原文件 | 4 MiB/文件 |
| 会话参考资料 | 最多 8 文件、32 MiB |
| 最终模型资料上下文 | 合计 128 KiB，包含来源元数据和 JSON 包装 |
| ZIP | 最多 2,048 项、单项展开 8 MiB、声明累计展开 32 MiB |
| XML | 累计 200,000 节点、64 层深度、每节点 64 个属性、累计读取 32 MiB |
| 输出 | 最多 10,000 条定位记录；工作表最多 20，幻灯片最多 100 |
| 子进程 | V8 堆上限 192 MiB，最长 20 秒；取消/超时终止并清理独有临时目录 |
| 单次引用准备 | 60 秒取消信号；逐文件处理 |
| Worker 读取并发 | 每个语言 Worker 进程 1 个下载/解析任务 |
| 解析缓存 | 每进程最多 32 项/4 MiB、10 分钟；键含用户、文件、校验和、读取版本；命中也重新验证数据库归属 |
| Web 上传/下载缓冲 | 各自每进程并发 2；下载每用户 30 次/分钟 |

ZIP 在解压前检查目录、路径、重复名称、头部一致性、重叠和大小；解压有真实输出上限并校验 CRC。XML 禁止 DTD/实体声明。结果缓存只针对 Office，向调用方返回副本，避免一次调用修改缓存污染后续请求。

子进程环境只带必要系统路径/临时目录/语言变量，不继承数据库、对象存储、模型凭据或 NODE_OPTIONS。**子进程与 V8 堆限制不是 OS 沙箱，也不是 RSS/CPU/磁盘硬限制**：部署必须另设容器/主机 CPU、内存、临时磁盘和网络边界。多副本总并发按副本数增长，当前排队门没有集群级解析配额。

没有把解析器装进画布按键/拖拽路径，也没有在上传 HTTP 请求中同步解压。浏览器测试检查了附件提交期间的脚本请求；尚未做生产 bundle 测量或原首页/画布/电商的完整性能基线，因此不能据此保证全站性能不回退。

## 准入和部署

默认不开启。Web/调度器的新 Office 请求需要 `CREATION_OFFICE_REFERENCES_ENABLED=true`，并且读取器心跳 `creation-reference-reader` 在 90 秒内、版本为 `office-reference-1`、`isolated:true`。

语言 Worker 主机必须显式声明 `CREATION_REFERENCE_ISOLATED=true` 才发布读取心跳；Office 已开启而主机未声明隔离时，Worker 启动拒绝。子进程入口也检查隔离声明。此声明是运维配置，并不自动建立隔离环境。

所有消费 `creation-language` 队列的实例必须使用匹配版本和隔离部署。当前 Office 与其他语言任务共用这个专用语言队列；不能仅加一个隔离实例、保留旧实例继续消费，再把全局心跳当作逐任务路由保证。旧实例拿到 Office 任务会失败，未实现按实例能力路由。

`saxes` **6.0.0** 从已安装的传递开发依赖提升为显式生产依赖，锁文件同步调整 `xmlchars` 生产归属。没有在本轮执行 npm 安装或下载；已静态核对 package/lock 版本和标记。生产镜像必须依照更新后的锁文件安装依赖，否则解析进程不可用。

本轮没有改环境开关、构建、启动数据库或队列 Worker、生成 Prisma client、迁移或部署。

## 本轮验证

最终 **15 个定向单元文件、73 个不同用例通过**，串行运行。最后一次汇总有 1 个旧测试替身缺少提前归属查询，补齐替身后该文件 7 个用例全部通过，未放松生产权限检查。另有 **1 个桌面/手机组合浏览器场景通过**，**34 个触及代码/测试文件 ESLint 通过**，参考资料 CSS 与生产依赖锁标记检查通过。

测试覆盖真实 ZIP/XML、三种实际项目导出包的反向读取、子进程/取消/超时、字节校验/限额、缓存归属、伪造压缩长度/DTD/宏/外链拒绝、空内容、任务准入/付费前失败/提交恢复、原件存储和鉴权下载响应。数据库/存储/模型为替身，不能当作真实事务或账务验收。

浏览器使用真实页面和模拟 API，验证中文 DOCX 原始字节上传、移除后复用无额外 POST、桌面/390px 布局、下载链接、提交 referenceIds 和无解析器脚本请求。Chromium 下载属性触发的下载绕过了本机 Playwright 路由拦截，实际命中无数据库的开发路由而失败；最终页面用例明确只验证链接，下载响应由路由单测验证。**未通过真实浏览器原件下载验收**，没有把此环境问题写成已修复产品问题。详见浏览器记录。

读取本项目导出包时发现并修正已有 PPTX 主 part MIME 缺少 `.main` 的问题，改为标准 `application/vnd.openxmlformats-officedocument.presentationml.presentation.main+xml`。已有 PPTX 导出用例增加正确类型断言，三格式往返读取通过，仍不替代 PowerPoint/WPS 打开验证。
