# 创作计划并发

创作计划不再按账号限制为一个。不同分镜项目、画布文档或创作会话可以独立提交和恢复计划，其他项目中等待输入、等待预算的计划不会占住整个账号。

## 冲突范围

- 图片与分镜计划：按 `userId + documentId` 检查未结束计划，避免同一文档被多个计划同时写入。
- Agent 与内容创作计划：按 `userId + sessionId` 检查，同一项目的不同会话可以分别创建计划。
- 创建、恢复和大纲确认使用相同的范围。恢复时排除当前计划，已验证的 Agent 父子计划继续使用原有排除规则。
- `queued`、`running`、`cancelling`、`awaiting_input`、`awaiting_budget` 仍占用自己的文档或会话；同范围冲突返回 `CREATION_SCOPE_BUSY`（HTTP 409）。

## 保留的保护

- 幂等键仍阻止重复提交和重复创建计划。
- 用户事务锁、积分预算、扣费与结算逻辑保持不变。
- 原有全局计划队列上限、模型任务并发限制和 Worker 并发配置保持不变；允许多计划不代表所有模型请求立即同时执行。
- 执行中遇到任务容量限制，调度器沿用原有等待与恢复机制。
- 文档版本检查、作品版本冲突保护和 Agent 父子关系验证保持不变。

## 部署与验证

无需数据库迁移，不会删除、取消或重新扣费已有计划。更新 Web 与相关创作 Worker 的应用镜像，确保所有准入入口使用同一版本；工具镜像无需因本项修改重新构建。

回归用例覆盖跨文档/会话准入、同范围阻止、恢复、大纲确认、幂等重放和全局队列限制。本机按资源限制仅做轻量静态检查，测试应在 CI 或资源充足的环境运行。
