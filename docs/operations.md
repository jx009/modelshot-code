# ModelShot 运行与恢复手册

本手册对应尚未上线的 V1 候选版本。真实供应商、支付、OAuth、邮件与部署验收见 `real-environment-acceptance.md`。本地演练不代表这些系统已通过验收。

## 启动

1. 安装 Node 22.23.2、npm 10.9.2、Docker 和 Python 3.11。
2. `npm ci`，再执行 `npm run setup:local`。该命令创建本地随机密钥、服务、私有 bucket 和迁移，不覆盖已有 `.env`。
3. `npm run db:seed` 初始化供应商及模板。缺少已核验图片的模特预设保持下架；也可使用工作台自定义模特上传。
4. 两个独立进程分别运行 `npm run dev` 和 `npm run worker`。正式构建使用 `npm run build`、`npm start` 和独立 Worker。
5. 浏览器进入 `/zh/studio`，本地邮件访问 `http://127.0.0.1:58025`。没有供应商配置时不能提交，浏览器测试使用仅测试库可见的本地供应商。

推荐初始 Worker 并发为 2，上限 8，队列消费限流 30 次/分钟。全局最多 2000 个活动输出，每用户最多 100 个；单次最多 50 件、100 个输出。调整前应复测数据库连接、内存和供应商限额。数据库是事实来源，Redis 不承担账本持久性。

原生依赖安装需能访问 GitHub releases 和 raw.githubusercontent.com。若 Windows 已设置系统代理但 Node 下载出现 ECONNRESET，在当前安装终端设置 HTTP_PROXY、HTTPS_PROXY 为本机已配置的代理，NO_PROXY 包含 localhost/127.0.0.1，并使用 Node 22.23.2 的 NODE_OPTIONS=--use-env-proxy 执行 npm ci。不要关闭所有安装脚本，也不要关闭 TLS 验证。C2PA 上游会下载自己的测试证书，应用不会自动使用这些证书签名；实际签名只接受显式配置的自有证书路径。

`GET /api/health` 只表示 Web 存活。`GET /api/ready` 校验配置、数据库、Redis、私有存储及 60 秒以内的 Worker 心跳。就绪失败返回 503，不返回内部连接信息。停止 Worker 时发送 SIGTERM，等待正在执行的有界操作及队列连接关闭。

## 账务政策

- 免费额度为 UTC 自然月 10 张。付费额度只按已支付 invoice 的实际起止区间发放；续费失败不预发额度，也没有额外付费宽限额度，旧周期到期后回到免费额度。
- 提交整单原子预留。私有存储中的有效原始图交付成功才确认消费；没有交付时释放。后处理与 QA 失败可独立重试，不再次生成、不再次收费。
- BYOK 不收平台生成积分，默认跳过平台付费 QA。供应商密钥不会跨通道复用。
- 排队取消立即释放；已提交供应商的取消尽力执行，若产物已交付仍正常消费。
- 供应商结果不明保留预留并对账 15 分钟，期限后关闭交付、释放资源。迟到结果隔离，平台承担潜在供应商费用。
- 订阅套餐变更下周期生效；取消为周期末取消，取消或恢复时解除尚未生效的换套餐安排。请求先落库再执行，账户页显示待处理状态。
- 真实货币全部是 USD cents 整数；积分和订阅额度单独记账。当前供应商 `costUsd` 是适配器成本估算，真实发票成本与商业毛利必须另行核验。

## 定位问题

`npm run ops -- status` 输出队列积压、最老等待、Outbox 延迟、未知结果、长期预留、支付错误与 Worker 心跳。管理后台 `/zh/admin/operations` 提供相同状态及支付事件、退款和审计记录。

初始告警阈值：Worker 心跳超过 60 秒、Outbox 超过 30 秒、排队超过 120 秒或超过 100 项、预留超过 30 分钟、任何未知结果和支付错误。阈值需要真实容量验证后校准。当前是结构化状态和本地模拟告警，未对接真实通知渠道。

错误响应具有 `code`、`retryable` 和 `traceId`。Worker 日志包含事件类型和实体 ID；任务记录与 attempt 表提供供应商请求 ID、fence、租约与错误码。排障不输出密钥、原图、完整提示词或授权 URL。

消费追踪：TryOn ID → CreditReservation.tryOnId → sourceTransactionId → CreditTransaction。预留的 allocations 指向 CreditLot，后者可指向购买 Order。订阅预留通过 cycleId 指向 BillingCycle 和实际 invoice。

`npm run ops -- reconcile` 在同一数据库快照检查预留、余额、额度周期、终态及消费来源，失败退出码为 1。不要直接修改余额或覆盖已有流水。

## 恢复流程

- Redis 丢失：恢复 Redis，运行 `npm run ops -- recover` 或等待 Worker 扫描。Outbox 和未终结工作会重建调度消息；重复消息由数据库条件与唯一业务键约束。
- Worker 中断：重启 Worker，等待租约过期。同步供应商受理后丢响应时转对账，不盲目再次生成；有请求查询能力的供应商按已保存 requestId 查询。
- 后处理失败：结果详情分别重试交付或 QA。原图保留，生成预留已结算，不再次扣费。导出失败或过期在导出记录重新建立任务。
- 支付错误：先查 eventId、orderId、币种、金额和实际支付状态；修复配置后 ROOT 在运行后台填写原因重放。事件收件箱与业务唯一键双重去重，不通过删除事件让系统重新发权益。
- 退款：ROOT 选择订单、输入美分金额和原因。请求落库后 Worker 调 Stripe；webhook 确认退款并回收对应购买批次未使用积分。已使用或被预留的权益进入人工审核，冻结尚存权益。待预留结束后可以回收剩余额度，将已消耗部分明确记为平台承担后结案。
- 佣金：线下付款核验后填写结算原因。退款冲回已结算佣金时记负向调整，影响下一次结算，不修改历史结算记录。
- 争议：等待支付平台最终裁决。胜诉后人工解除审核；已落库的败诉结案事件允许 ROOT 核验原因后按拒付金额回收权益和冲回佣金，保留 chargeback 状态。仍在裁决中的争议不能人工绕过结案。
- 超过 23 小时仍未确认的外部写操作停止自动重发，以免超过供应商幂等保存期限。退款先查询原 payment intent 的退款记录；无法确认的退款与订阅变更进入 review，须在支付平台核验后处理，不能直接创建新的同类操作。

review 结案入口在运行后台：填写支付平台查询记录或工单编号、操作原因和已核实结果。退款仅允许确认未执行并关闭请求，已成功的退款应重放对应真实 webhook 完成账务确认。订阅变更可确认已执行/未执行；结案写审计并解除阻塞，不重新调用支付平台。切勿把“尚不确定”选为“未执行”。

## 私有素材

用户只能读取自己的素材。管理员审计读取图片使用独立路由并先写审计记录。公开目录只允许已获得使用授权的预设，不能写入用户上传；旧公开 uploads 不参与新流程。

删除先检查引用并标记，7 天后 `npm run ops -- cleanup` 才删除对象。草稿、任务或导出仍引用的图片不能删除。导出 24 小时过期，清理对象和导出引用。账务和审计不随用户归档删除。

`npm run ops -- cleanup-orphans` 扫描私有 bucket，仅清理超过 24 小时、无资产或导出记录且不属于活动任务的已知路径对象。配置 bucket 必须只供本项目使用。数据库引用异常先执行恢复与对账，再处理孤立对象。

## 密钥轮换与权限

Web 与 Worker 使用同一版本化密钥集合。准备新的 64 位 hex `ENCRYPTION_KEY` 与 `ENCRYPTION_KEY_VERSION`，保留旧版本为 `ENCRYPTION_KEY_<版本>`。运行 `npm run ops -- rotate-keys <ROOT用户ID> "轮换原因"`，检查成功后重启全部进程，确认没有旧版本凭据再移除旧密钥。命令在事务中重新加密并写审计，不打印明文。

验证码密钥按版本保留到所有旧验证码过期。不要同时删除正在使用的 NEXTAUTH_SECRET 和旧验证码解密所需版本。封禁、改密和撤销凭据会使旧会话失效。

权限矩阵：user/agent 管理自己的素材、任务和账户；admin 可查看运行数据并管理低权限用户；root 可调整角色、平台配置、退款与审核。任何管理员都不能通过用户管理修改自己或同级/更高级用户，不能创建第二个 root。首个 root 应由受控部署管理流程对已验证的账户授权。

生产使用独立数据库迁移账号。Web/Worker 数据账号只授予应用表读写权限，禁止数据库管理权限；S3 仅授权本项目私有 bucket，限制 CORS 和公网访问；Redis 仅内网与 ACL；数据库与服务端口不得照搬本地开发密码对公网开放。平台供应商代理只能使用 `PROVIDER_PROXY_HOSTS` 中受信任的 HTTPS 主机。

## 备份与发布

数据库和私有对象必须作为一套可恢复资源备份，保留对象版本与加密密钥。发布前执行 `prisma migrate deploy`，禁止正式库使用 db push。本项目没有历史数据，不执行账户合并或历史账务回填。

本地 `npm run test:recovery` 在专用测试库创建合成账务值，用 pg_dump/pg_restore 恢复到独立 `modelshot_restore_test`，核对后清理临时库。不会回滚开发库。真实环境需另测备份加密、RPO/RTO、对象版本和恢复耗时。

回滚优先停用支付/供应商入口并回退应用。不得恢复旧数据库快照来抹除已发生的新付款、扣费或退款；应使用事件重放和有来源的补偿记录。上线前保留最后一次应用构建、迁移版本、依赖审计和验收报告。
